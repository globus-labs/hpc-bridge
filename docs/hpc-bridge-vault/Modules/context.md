# context

> [!abstract] Role
> The server's runtime state as pure data: `AppCtx` (one per server, shared by every tool call), `ShapeRuntime` (per resource shape: Executor, warmth/canary, spend clock, the sticky no-account verdict), `TaskHandle` (a command still running past the sync-wait), and `DEFAULT_SHAPE`, plus the derived reads on them (`_supported_shapes`, `_has_login_shape`, `_no_facility_bound`, `_idle_release_s`). No behaviour lives here.

Split step 1 of the [[Review 2026-09-03 — code quality|code-quality review]]'s plan (2026-09-03): a leaf module so the modules that follow (config, notices, warmth, tasks, …) can import the state without importing `server`. `server` re-exports the four names, so `from hpc_bridge.server import AppCtx` — every test and tool — keeps working. Field-level rationale comments moved with the fields. `TaskHandle.client_cancelled` marks a command whose call the client cancelled mid sync-wait. It is tracked like any running task, and the flag only lets the notices explain a task id the agent never received. `TaskHandle.runtime` is the shape runtime the task was dispatched on. A task whose block was released under it is noted nowhere else (never on a rebuilt or newer runtime). `TaskHandle.reset` marks a `reset_session`, for its notices. `AppCtx.released_inflight` holds compute runtimes dropped while a call was still in its sync-wait on them. A stop still sees that call while the endpoint it went to is the bound one. `LeftBlock` / `AppCtx.left_blocks` record the blocks (or a queued check) a facility-MEP stop, detach, reconnect or switch let go without a cancel (no cancel channel there, [#178](https://github.com/globus-labs/hpc-bridge/issues/178)) — job, kind, latest end, when and how, partition and account, whether hpc-bridge confirmed it — ONLY so later notices still name them, never to bill them again; `AppCtx.billed_to` is the per-(endpoint, job) high-water mark of what a stop's bank has counted, so a later tail for that job adds only what is beyond it; `AppCtx.worker_user` is the local account the last check ran as (the facility's identity mapping), for `squeue -u`. `ShapeRuntime.confirmed_at` (`:122`) is when spend was last confirmed (an earlier session's dead pilot is left out of the verdict by it) and `ShapeRuntime.unseen_terms` (`:91`) the old terms of a block a switch left still landing. `ShapeRuntime.rejected` (`:112`) is a submission the scheduler rejected (its cause and terms; [[warmth]] `_void_rejected`) and `ShapeRuntime.dead_pilot` (`:119`) a pilot that ran and died before any worker answered (a `DeadPilot`, `:184`: its job, exit status, and every pilot job seen with it). `AppCtx.pilot_watch` (`:306`) keeps, per SSH endpoint, a `PilotWatch` (`:199`): a pilot of ours that may still land after a stop let the shape go — a block still being submitted, or a dead pilot whose check is still queued — so a second stop looks again; keyed by endpoint, it survives the stop's drop and a reconnect, and goes with a `down` stop (a dropped shape hands its dead pilot to it, a re-bind included), a worker answering on its terms, a rejected submission there, and the endpoint's teardown. `AppCtx.terms_origin` (a `TermsOrigin`, [[models]]) is where the bound facility's default partition and account came from — the registry, an env preset, a facility you bring yourself (its details, or the probe's proposal they kept) — whether its entry says an account is needed, and its `account_hint`; [[connect]] records it at the bind, `server.lifespan` from the startup pin (`binding._PINNED_ORIGIN`); `notices._block_terms` reads it for every block's terms.

`_no_facility_bound(app)` (`context.py:324`) is true while the facility is the server's implicit local default (no machine pinned or connected, local dev not opted into: the `implicit` mark that [[binding]] `_default_local_facility` sets, never the facility's type). `AppCtx.proposed_facility` (`:238`) is the id the LAST `connect_facility` answered with `proposed_facility_details`; the no-facility notice names it, and every connect clears it first ([[connect]]).
