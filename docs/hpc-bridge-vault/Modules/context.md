# context

> [!abstract] Role
> The server's runtime state as pure data: `AppCtx` (one per server, shared by every tool call), `ShapeRuntime` (per resource shape: Executor, warmth/canary, spend clock, the sticky no-account verdict), `TaskHandle` (a command still running past the sync-wait), and `DEFAULT_SHAPE`, plus the derived reads on them (`_supported_shapes`, `_has_login_shape`, `_no_facility_bound`, `_idle_release_s`). No behaviour lives here.

Split step 1 of the [[Review 2026-09-03 — code quality|code-quality review]]'s plan (2026-09-03): a leaf module so the modules that follow (config, notices, warmth, tasks, …) can import the state without importing `server`. `server` re-exports the four names, so `from hpc_bridge.server import AppCtx` — every test and tool — keeps working. Field-level rationale comments moved with the fields. `TaskHandle.client_cancelled` marks a command whose call the client cancelled mid sync-wait. It is tracked like any running task, and the flag only lets the notices explain a task id the agent never received. `TaskHandle.runtime` is the shape runtime the task was dispatched on. A task whose block was released under it is noted nowhere else (never on a rebuilt or newer runtime). `TaskHandle.reset` marks a `reset_session`, for its notices. `AppCtx.released_inflight` holds compute runtimes dropped while a call was still in its sync-wait on them. A stop still sees that call while the endpoint it went to is the bound one. `LeftBlock` / `AppCtx.left_blocks` record the blocks (or a queued check) a facility-MEP stop, detach, reconnect or switch let go without a cancel (no cancel channel there, [#178](https://github.com/globus-labs/hpc-bridge/issues/178)) — job, kind, latest end, when and how, partition and account, whether hpc-bridge confirmed it — ONLY so later notices still name them, never to bill them again; `AppCtx.billed_to` is the per-(endpoint, job) high-water mark of what a stop's bank has counted, so a later tail for that job adds only what is beyond it; `AppCtx.worker_user` is the local account the last check ran as (the facility's identity mapping), for `squeue -u`. `ShapeRuntime.confirmed_at` (`:117`) is when spend was last confirmed (an earlier session's dead pilot is left out of the verdict by it). `ShapeRuntime.rejected` (`:107`) is a submission the scheduler rejected (its cause and terms; [[warmth]] `_void_rejected`) and `ShapeRuntime.dead_pilot` (`:114`) a pilot that ran and died before any worker answered (a `DeadPilot`, `:179`: its job, exit status, and every pilot job seen with it). `AppCtx.sent_checks` keeps, per endpoint, the `SentCheck`s: tasks of ours not seen to finish — a check the compute runners it retired had sent and no worker had answered, or a command whose result the client lost (`what`) — each with the SDK future (None when read back from disk), the SDK Client that looks it up, its `task_id` (`tid`), when it was sent, the partition and account it asked for, a dead pilot to name the block request it was sent for (`block`: what names its compute user endpoint on the login node, [[server]] `_settle_by_evidence`) and when its task id was first seen (`taken_at`, wall clock, written to the record; `taken_mono`, monotonic, in-process only: what that evidence dates it by) — since one still queued can make the endpoint start a block (#24, [[warmth]] `_retire_runner`). Keyed by endpoint, it survives a stop's drop, a switch, a reconnect and (on disk, [[state]] `SentCheckStore`) a restart; a stop drops what it found resolved, the endpoint's teardown the rest. `AppCtx.persisted_checks` is what this process last wrote and removed per endpoint, so the file is rewritten only on a change (and again after a failed write); `AppCtx.resolved_checks` the resolutions seen this session by task id — never asked again, and removed from the record by this process. A `DeadPilot` (`:179`) now only names a pilot. `AppCtx.terms_origin` (a `TermsOrigin`, [[models]]) is where the bound facility's default partition and account came from — the registry, an env preset, a facility you bring yourself (its details, or the probe's proposal they kept) — whether its entry says an account is needed, and its `account_hint`; [[connect]] records it at the bind, `server.lifespan` from the startup pin (`binding._PINNED_ORIGIN`); `notices._block_terms` reads it for every block's terms.

`_no_facility_bound(app)` (`context.py:324`) is true while the facility is the server's implicit local default (no machine pinned or connected, local dev not opted into: the `implicit` mark that [[binding]] `_default_local_facility` sets, never the facility's type). `AppCtx.proposed_facility` (`:244`) is the id the LAST `connect_facility` answered with `proposed_facility_details`; the no-facility notice names it, and every connect clears it first ([[connect]]).

`SeenPilots` (2026-10-20, `polaris_filesystems`) is the record of the live pilots a provisioning probe listed for the endpoint — (job, state, reason, word) each (the word: the state as the scheduler listed it, Slurm's PENDING or PBS's Q, which a reconnect's note names; round 4, #1), oldest first, when it looked, and the pilot its verdict was about — with the states [[scheduler_ops]] `_pilot_state` gives (H held, N refused as submitted, R running, any other letter waiting); `ShapeRuntime.pilots` holds the latest, `switch_left_pilots` what a switch left. `SshLeft` is what a re-bind leaves of an SSH endpoint's compute shape (the block that was up, those pilots), kept per endpoint in `AppCtx.ssh_left`; `AppCtx.directive_notes` keeps a connect's report of rewritten `scheduler_options` until a result carries it, or until the details= config it describes is dropped ([[connect]]).

**Resource requests (2026-10-24).** `AppCtx.compute_choice` is `dict[str, Any]` now: the size keys
([[resources]] `SIZE_KEYS`) persist there beside the partition and account, a key set to None being one the session
cleared. `ShapeRuntime.switched_terms` / `reap_terms` are `(partition, account, size)` (warmth `_block_key`);
`rejected_size` is a rejected block's size.

**Configs read from the cache (2026-10-29).** `AppCtx.from_cache` marks the facility ids whose `session_facilities`
config the cache rung read from `facilities.json` (id → the `ssh_host` the call named, None when found under the id). It
lets [[connect]] drop such a config when its bring-up fails or hands off, and re-read the record for that host on the
next connect (Perlmutter report, left-over local state). A `details=` for the id removes the mark.
