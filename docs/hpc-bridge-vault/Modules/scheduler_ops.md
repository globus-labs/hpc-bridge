# scheduler_ops

> [!abstract] Role
> The scheduler-facing shell one-liners that ride the FREE login shape: cancel this endpoint's blocks (`_release_cmd` → `scancel`/`qdel` scoped by the `uep.<eid>` StdOut marker; `_release_blocks_over_login` retries a cold channel `HPC_BRIDGE_RELEASE_ATTEMPTS` × backoff and reports an HONEST unconfirmed result), and read the pilot job's state (`_pilot_status_cmd`, `_summarize_pilot`: starting / queued / held / rejected, with the `PROVISION_GRACE_S` window so a not-yet-visible pilot isn't cried as rejected — #32; `_augment_provisioning_notice` appends the verdict; for a held pilot it offers `connect_facility(details=…)` only on a bring-your-own facility, since a registry entry's directives and walltime cannot be changed per session — `own_config`). For each pilot that FINISHED with an exit status of its own, the command also reads THAT job's stderr (Slurm: sacct's SubmitLine script + `.stderr`; PBS: Error_Path) and `_SAID_LOOP` (`:133`) emits `HPCB_SAID <job> <line>` for a line starting `hpc-bridge: ` (a tag no scheduler state uses: PBS has a `W` state). Only the newest died pilot's exact `endpoint venv … (built on A) does not run on … (B)` line is quoted, and only in the FINISHED notice: `_venv_verdict` (`:269`) says a rebuild cannot help when A ≠ B, and offers teardown + connect when they match. The facility's `worker_init_note` (an endpoint started with another env_setup) rides only a FINISHED pilot.

**A failed scheduler command is said, never read as empty.** `_release_cmd` (`:32`) prints `release failed: <command> could not be read` when the listing (`squeue` / `qstat -f`) fails; it cancels one job at a time (one call for all fails as a whole when PBS refuses a job already exiting, and cannot say which), so a refused cancel reads `release failed: <cancel> refused <ids>; cancelled: <ids>` — what it did cancel is kept (`_released_jobs`), and `_release_failure` quotes the failure for the stop; `_release_blocks_over_login` (`:69`) confirms only a `released …` line. The probe prints `HPCB_FAIL <command>` for a failed `squeue` / `sacct` / `qstat`, `HPCB_NOW <epoch>` (the login node's clock) and `HPCB_SUB <job> <epoch>` per finished pilot (sacct's Submit under `SLURM_TIME_FORMAT=%s`; PBS's `ctime`, turned into epoch seconds by `_SAID_LOOP` with GNU date). A failed live listing reads `unknown` — no verdict, never "no pilot".

**The probe as data.** `_probe_pilots_over_login` (`:351`) returns a `PilotProbe` (`:324`): the summary, every pilot job it listed (live or finished), each that FINISHED with an exit status of its own (`_pilot_rows` `:217`, `_died` `:224`, which `_summarize_pilot` reads too), the live ones and the failed commands; `.dead` is the pilot a FINISHED verdict names. With `confirmed_at` (the block's confirmation; its age is read once the probe is back, so a slow probe only moves the cutoff toward counting) a finished pilot submitted before it, less `_SUBMIT_SLACK_S` (`:348`, 60 s), is an earlier session's and left out of the verdict; one with no submit time counts. `_augment_provisioning` (`:396`) hands back the notice and the probe, so [[server]] `_ensure_endpoint_up` records a pilot that ran and died (`ShapeRuntime.dead_pilot`); `_augment_provisioning_notice` and `_pilot_status_over_login` keep their old shapes. A stop does not read it: its evidence is our check's own state ([[server]] `_stop_endpoint`), and the probe's dead pilot only names what became of that check. `_released_jobs` (`:106`) reads the jobs a release cancelled (a confirmed `released …`, or the `cancelled:` part of a partial one), which a stop's repeated releases add up.

**A check's own user endpoint, read on the login node** (`_uep_evidence_cmd` `:444`, `_read_uep_evidence` `:503`, `UepEvidence` `:491`; [[server]] `_settle_by_evidence` runs it). For a check the service still lists as queued after a stop's wait — its user endpoint may have failed it and lost the report (globus-compute-endpoint 4.18 stops its result publisher without blocking, right after bad state) — the one-liner reports, for each block request asked about, the compute user endpoint whose `endpoint.log` names it (`running endpoint_setup command: true hpcb_block=<n>`, [[facility-remote]] `BLOCK_REQUEST_LOG`): `HPCB_UEP <n> <uuid> <starts> <last start line> <last token line> <last bad-state line> <shutdown line after it> <date> <time>` (awk, one pass, bounded: the last `========== Endpoint begins:`, the last timestamped `Setting bad state` since it, a `---------- Endpoint shutdown:` after that), then `HPCB_PS <uuid> <count>` (processes whose arguments name `uep.<eid>.<uuid>` — the user endpoint's title does; the list is read BEFORE the loop, and the script names no user endpoint's id, so it never counts itself) and `HPCB_PID <uuid> none|old|fresh|unknown` (`daemon.pid`, refreshed every 15 s while it lives; `find -mmin -2`), with `HPCB_NOW <epoch> <date> <time>` (one `date` call) and `HPCB_FAIL ps|read <uuid>`. POSIX sh, awk, `ps -ww -U`, `find`, `date`; read-only; built only from a UUID endpoint id and whole-number block requests (else a ValueError), the user endpoint's id read from its directory name and used only when it is a UUID's characters, inside double quotes or as awk data. `_read_uep_evidence` takes only rows of that exact shape and reads every doubt as no evidence; a bad state counts only `_EVIDENCE_SLACK_S` (2 s) after the send placed on the login node's clock (the age measured before the command, so the send is never placed earlier than it was; a log line's local time is read against the same `date` call's local time — every user endpoint, the login shape's included, is forked by one manager with its environment, so they log in that zone) and never ahead of that clock. Fixtures: `tests/uep_log_fixtures/` (the two bundles' user endpoint logs, verbatim).

It also recognises a scheduler job the agent submits **by hand**: `_scheduler_submission` (`:921`) returns `sbatch`/`qsub`/`salloc`/`srun` when a command starts a NEW job (`inside_job=True` on the compute shape, where `srun` is a step of the block's own job; `srun --jobid` is a step anywhere), and `_submission` (`:940`) adds what the exit code can say — how many submit calls the line makes, and whether the line's exit code is the one call's own answer (`own_exit`: its last command, run directly — not under `timeout`/`xargs`/`bash -c` — and not waiting for the job, `_waits`) — for `_submission_refused` (`:957`, which also wants no job receipt, `_RECEIPT`). `_lex` (`:664`) is a one-pass, linear-time lexer: quotes removed, comments and here-document bodies dropped (a `<<EOF` inside quotes or a comment is not one), command substitutions cut out (`_subst_end` is quote-aware: `$(echo ")")`) and read at a capped depth (`_MAX_DEPTH`); `_group` (`:760`) leaves out a function body defined in the command and the patterns of a `case` (after `;;`, `*/qsub)` is a pattern); `_submit_call` (`:873`) walks past keywords, `VAR=…`, redirections and wrappers with their own arguments (`_past_wrapper`: `timeout -s KILL 60`, `nice -n 10`, `env -u X`, `xargs -n1`, `sudo -u`; `command -v` only among command's own options), into `bash -c`, `eval` and `find -exec`; `_starts_job` (`:852`) reads the scheduler's own options only before the first positional word (`_leading_options` knows which take a value), so `srun python --version` still submits, and `--help`/`--version`/`--test-only` (Slurm's `-h`/`-V` too; not PBS's, where `qsub -h` holds a job it still submits) are queries. Pure and precision-first; `server._detect_submission` calls it. Its cases live in `tests/submission_corpus.py`, shared with the harness grader.

The first step that needed **injection**: these ops run commands through `run_shell(shape="login")`, which lives in [[server]]; importing it back would be a cycle, so the login-shape channel is a parameter (`run_login`) that `server._login_runner(app)` builds at call time. Tests that patch `server._run_shell` therefore still reach every op; tests that patch the release call patch `scheduler_ops._release_blocks_over_login`. The harness keeps a DELIBERATE copy of `_release_cmd` (see [[Review 2026-09-03 — code quality]] D11) pinned by a test to the same marker scoping.
