# scheduler_ops

> [!abstract] Role
> The scheduler-facing shell one-liners that ride the FREE login shape: cancel this endpoint's blocks (`_release_cmd` → `scancel`/`qdel` scoped by the `uep.<eid>` StdOut marker; `_release_blocks_over_login` retries a cold channel `HPC_BRIDGE_RELEASE_ATTEMPTS` × backoff and reports an HONEST unconfirmed result), and read the pilot job's state (`_pilot_status_cmd`, `_summarize_pilot`: starting / queued / held / rejected, with the `PROVISION_GRACE_S` window so a not-yet-visible pilot isn't cried as rejected — #32; `_augment_provisioning_notice` appends the verdict; for a held pilot it offers `connect_facility(details=…)` only on a bring-your-own facility, since a registry entry's directives and walltime cannot be changed per session — `own_config`). For each pilot that FINISHED with an exit status of its own, the command also reads THAT job's stderr (Slurm: sacct's SubmitLine script + `.stderr`; PBS: Error_Path) and `_SAID_LOOP` (`:132`) emits `HPCB_SAID <job> <line>` for a line starting `hpc-bridge: ` (a tag no scheduler state uses: PBS has a `W` state). Only the newest died pilot's exact `endpoint venv … (built on A) does not run on … (B)` line is quoted, and only in the FINISHED notice: `_venv_verdict` (`:268`) says a rebuild cannot help when A ≠ B, and offers teardown + connect when they match. The facility's `worker_init_note` (an endpoint started with another env_setup) rides only a FINISHED pilot.

**A failed scheduler command is said, never read as empty.** `_release_cmd` (`:31`) prints `release failed: <command> could not be read` when the listing (`squeue` / `qstat -f`) fails; it cancels one job at a time (one call for all fails as a whole when PBS refuses a job already exiting, and cannot say which), so a refused cancel reads `release failed: <cancel> refused <ids>; cancelled: <ids>` — what it did cancel is kept (`_released_jobs`), and `_release_failure` quotes the failure for the stop; `_release_blocks_over_login` (`:68`) confirms only a `released …` line. The probe prints `HPCB_FAIL <command>` for a failed `squeue` / `sacct` / `qstat`, `HPCB_NOW <epoch>` (the login node's clock) and `HPCB_SUB <job> <epoch>` per finished pilot (sacct's Submit under `SLURM_TIME_FORMAT=%s`; PBS's `ctime`, turned into epoch seconds by `_SAID_LOOP` with GNU date). A failed live listing reads `unknown` — no verdict, never "no pilot".

**The probe as data.** `_probe_pilots_over_login` (`:350`) returns a `PilotProbe` (`:323`): the summary, every pilot job it listed (live or finished), each that FINISHED with an exit status of its own (`_pilot_rows` `:216`, `_died` `:223`, which `_summarize_pilot` reads too), the live ones and the failed commands; `.dead` is the pilot a FINISHED verdict names. With `confirmed_at` (the block's confirmation; its age is read once the probe is back, so a slow probe only moves the cutoff toward counting) a finished pilot submitted before it, less `_SUBMIT_SLACK_S` (`:347`, 60 s), is an earlier session's and left out of the verdict; one with no submit time counts. `_augment_provisioning` (`:395`) hands back the notice and the probe, so [[server]] `_ensure_endpoint_up` records a pilot that ran and died (`ShapeRuntime.dead_pilot`); `_augment_provisioning_notice` and `_pilot_status_over_login` keep their old shapes. A stop does not read it: its evidence is our check's own state ([[server]] `_stop_endpoint`), and the probe's dead pilot only names what became of that check. `_released_jobs` (`:105`) reads the jobs a release cancelled (a confirmed `released …`, or the `cancelled:` part of a partial one), which a stop's repeated releases add up.

**A check's own user endpoint, read on the login node** (`_uep_evidence_cmd`, `_read_uep_evidence`, `_uep_verdict`; [[server]] `_settle_by_evidence` runs it). For a check the service still lists as queued after a stop's wait — its user endpoint may have failed it and lost the report (globus-compute-endpoint 4.18 stops its result publisher without blocking, right after bad state). The module comment lists what the evidence must rule out and how: the check running (it was taken at least `_DELIVERY_S`, 1 s, before the latest life's bad state, in a life already subscribed — `Awaiting messages from queue` —, so that life received and acked it; a task arriving during a quiesce is not acked) and that user endpoint starting again (a revival from a cached start request, or a start for a new task; any new life starts a block). The one-liner takes TWO samples `_EVIDENCE_GAP_S` (3 s) apart — past the manager's reap, which runs between its 1 s command-queue polls, and the revival it logs at once — and the reader wants them to agree. Per sample: `HPCB_NOW <S> <epoch> <ns>`; `HPCB_FAIL <S> ps|read <id>|manager <n>`; for each user endpoint whose log names a wanted block request (`grep -lF` over this endpoint's user endpoint logs, confirmed exactly by `_UEP_AWK`) `HPCB_UEP <S> <n> <id> <starts> <start> <request> <subscribed> <bad> <shutdown> <lines> <pid> <date> <time> <epoch> <dst> <µs>` — the bad state's local time turned into epoch seconds ON the login node in its zone (GNU `date -d`, else BSD `date -j -f`), `<dst>` 1 for an hour a clock change repeats (never used); `HPCB_PS <S> <id> <count>` (the list read before anything names an id); `HPCB_PID <S> <id> none|old|fresh|unknown`; and from the MANAGER's own log (the one `endpoint.log` outside the user endpoints' directories that names `Core Endpoint begins: <eid>`) `HPCB_MGR <S> <id> <start line> <pid> <exit line> <pid> <last line naming it>` (`_MGR_AWK`: `Creating new user endpoint (pid: P)`, `Command stopped normally (P)` / return code / signal; the reader wants the exit after the start, the same pid as the life's own log, and nothing after it). Every check of ours must be at least `_EVIDENCE_SETTLED_S` (35 s) old, from when its task id was first seen (the start request the service sent with it acted on or expired with the manager's 30 s grace). The manager's directory is the one outside `uep.*` whose `endpoint.json` names the endpoint id, or whose `endpoint.log` or its one rotated copy (`endpoint.log.1`: 100 MB, one backup) names `Core Endpoint begins: <eid>`; its log is read through the rotation, the copy first (a start rotated out entirely is no evidence). A user endpoint whose log cannot be read gets its own `HPCB_PS`/`HPCB_PID`/`HPCB_MGR` rows, and must be provably stopped (no process, pid file gone or stale, and the manager never named it or logged its exit with nothing after — `_stopped_for_good`), else it may be a live twin naming the same block request and every check is void; only a check no readable log names is void otherwise. A read error grep meets (exit 2: EIO, a stale NFS handle — `[ -r ]` checks permissions only) prints `HPCB_FAIL <S> grep`, never an empty match. POSIX sh, awk, `ps -ww -U`, `find`, `date`; read-only; built only from a UUID endpoint id, whole-number block requests and a gap in (0, 10] s (else a ValueError), a user endpoint's id used only when it is a UUID's characters; the reader takes only rows of the exact shape (`_DIGITS`, never `str.isdigit`, which takes `²`). Fixtures: `tests/uep_log_fixtures/` (three cells' manager and user endpoint logs, verbatim; `live_*` from this template, settled live).

It also recognises a scheduler job the agent submits **by hand**: `_scheduler_submission` (`:1026`) returns `sbatch`/`qsub`/`salloc`/`srun` when a command starts a NEW job (`inside_job=True` on the compute shape, where `srun` is a step of the block's own job; `srun --jobid` is a step anywhere), and `_submission` (`:1045`) adds what the exit code can say — how many submit calls the line makes, and whether the line's exit code is the one call's own answer (`own_exit`: its last command, run directly — not under `timeout`/`xargs`/`bash -c` — and not waiting for the job, `_waits`) — for `_submission_refused` (`:1062`, which also wants no job receipt, `_RECEIPT`). `_lex` (`:769`) is a one-pass, linear-time lexer: quotes removed, comments and here-document bodies dropped (a `<<EOF` inside quotes or a comment is not one), command substitutions cut out (`_subst_end` is quote-aware: `$(echo ")")`) and read at a capped depth (`_MAX_DEPTH`); `_group` (`:865`) leaves out a function body defined in the command and the patterns of a `case` (after `;;`, `*/qsub)` is a pattern); `_submit_call` (`:978`) walks past keywords, `VAR=…`, redirections and wrappers with their own arguments (`_past_wrapper`: `timeout -s KILL 60`, `nice -n 10`, `env -u X`, `xargs -n1`, `sudo -u`; `command -v` only among command's own options), into `bash -c`, `eval` and `find -exec`; `_starts_job` (`:957`) reads the scheduler's own options only before the first positional word (`_leading_options` knows which take a value), so `srun python --version` still submits, and `--help`/`--version`/`--test-only` (Slurm's `-h`/`-V` too; not PBS's, where `qsub -h` holds a job it still submits) are queries. Pure and precision-first; `server._detect_submission` calls it. Its cases live in `tests/submission_corpus.py`, shared with the harness grader.

The first step that needed **injection**: these ops run commands through `run_shell(shape="login")`, which lives in [[server]]; importing it back would be a cycle, so the login-shape channel is a parameter (`run_login`) that `server._login_runner(app)` builds at call time. Tests that patch `server._run_shell` therefore still reach every op; tests that patch the release call patch `scheduler_ops._release_blocks_over_login`. The harness keeps a DELIBERATE copy of `_release_cmd` (see [[Review 2026-09-03 — code quality]] D11) pinned by a test to the same marker scoping.
