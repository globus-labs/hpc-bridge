# scheduler_ops

> [!abstract] Role
> The scheduler-facing shell one-liners that ride the FREE login shape: cancel this endpoint's blocks (`_release_cmd` → `scancel`/`qdel` scoped by the `uep.<eid>` StdOut marker; `_release_blocks_over_login` retries a cold channel `HPC_BRIDGE_RELEASE_ATTEMPTS` × backoff and reports an HONEST unconfirmed result), and read the pilot job's state (`_pilot_status_cmd`, `_summarize_pilot`: starting / queued / held / rejected, with the `PROVISION_GRACE_S` window so a not-yet-visible pilot isn't cried as rejected — #32; `_augment_provisioning_notice` appends the verdict).

It also recognises a scheduler job the agent submits **by hand**: `_scheduler_submission` (`:563`) returns `sbatch`/`qsub`/`salloc`/`srun` when a command starts a NEW job (`inside_job=True` on the compute shape, where `srun` is a step of the block's own job; `srun --jobid` is a step anywhere), and `_submission` (`:582`) adds what the exit code can say — how many submit calls the line makes, and whether the line's exit code is the one call's own answer (`own_exit`: its last command, run directly — not under `timeout`/`xargs`/`bash -c` — and not waiting for the job, `_waits`) — for `_submission_refused` (`:599`, which also wants no job receipt, `_RECEIPT`). `_lex` (`:306`) is a one-pass, linear-time lexer: quotes removed, comments and here-document bodies dropped (a `<<EOF` inside quotes or a comment is not one), command substitutions cut out (`_subst_end` is quote-aware: `$(echo ")")`) and read at a capped depth (`_MAX_DEPTH`); `_group` (`:402`) leaves out a function body defined in the command and the patterns of a `case` (after `;;`, `*/qsub)` is a pattern); `_submit_call` (`:515`) walks past keywords, `VAR=…`, redirections and wrappers with their own arguments (`_past_wrapper`: `timeout -s KILL 60`, `nice -n 10`, `env -u X`, `xargs -n1`, `sudo -u`; `command -v` only among command's own options), into `bash -c`, `eval` and `find -exec`; `_starts_job` (`:494`) reads the scheduler's own options only before the first positional word (`_leading_options` knows which take a value), so `srun python --version` still submits, and `--help`/`--version`/`--test-only` (Slurm's `-h`/`-V` too; not PBS's, where `qsub -h` holds a job it still submits) are queries. Pure and precision-first; `server._detect_submission` calls it. Its cases live in `tests/submission_corpus.py`, shared with the harness grader.

Split step 6 (2026-09-03). The first step that needed **injection**: these ops run commands through `run_shell(shape="login")`, which lives in [[server]]; importing it back would be a cycle, so the login-shape channel is a parameter (`run_login`) that `server._login_runner(app)` builds at call time. Tests that patch `server._run_shell` therefore still reach every op; tests that patch the release call patch `scheduler_ops._release_blocks_over_login`. The harness keeps a DELIBERATE copy of `_release_cmd` (see [[Review 2026-09-03 — code quality]] D11) pinned by a test to the same marker scoping.
