# scheduler_ops

> [!abstract] Role
> The scheduler-facing shell one-liners that ride the FREE login shape: cancel this endpoint's blocks (`_release_cmd` → `scancel`/`qdel` scoped by the `uep.<eid>` StdOut marker; `_release_blocks_over_login` retries a cold channel `HPC_BRIDGE_RELEASE_ATTEMPTS` × backoff and reports an HONEST unconfirmed result), and read the pilot job's state (`_pilot_status_cmd`, `_summarize_pilot`: starting / queued / held / rejected, with the `PROVISION_GRACE_S` window so a not-yet-visible pilot isn't cried as rejected — #32; `_augment_provisioning_notice` appends the verdict; for a held pilot it offers `connect_facility(details=…)` only on a bring-your-own facility, since a registry entry's directives and walltime cannot be changed per session — `own_config`). For each pilot that FINISHED with an exit status of its own, the command also reads THAT job's stderr (Slurm: sacct's SubmitLine script + `.stderr`; PBS: Error_Path) and `_SAID_LOOP` (`:123`) emits `HPCB_SAID <job> <line>` for a line starting `hpc-bridge: ` (a tag no scheduler state uses: PBS has a `W` state). Only the newest died pilot's exact `endpoint venv … (built on A) does not run on … (B)` line is quoted, and only in the FINISHED notice: `_venv_verdict` (`:259`) says a rebuild cannot help when A ≠ B, and offers teardown + connect when they match. The facility's `worker_init_note` (an endpoint started with another env_setup) rides only a FINISHED pilot.

**A failed scheduler command is said, never read as empty.** `_release_cmd` (`:29`) prints `release failed: <command> …` when the listing (`squeue` / `qstat -f`) or the cancel fails, and every cancelled id on its one `released …` line; `_release_blocks_over_login` (`:63`) confirms only a `released …` line. The probe prints `HPCB_FAIL <command>` for a failed `squeue` / `sacct` / `qstat`, `HPCB_NOW <epoch>` (the login node's clock) and `HPCB_SUB <job> <epoch>` per finished pilot (sacct's Submit under `SLURM_TIME_FORMAT=%s`; PBS's `ctime`, turned into epoch seconds by `_SAID_LOOP` with GNU date). A failed live listing reads `unknown` — no verdict, never "no pilot".

**The probe as data.** `_probe_pilots_over_login` (`:341`) returns a `PilotProbe` (`:314`): the summary, every pilot job it listed (live or finished), each that FINISHED with an exit status of its own (`_pilot_rows` `:207`, `_died` `:214`, which `_summarize_pilot` reads too), the live ones and the failed commands; `.dead` is the pilot a FINISHED verdict names. With `since_s` (since the block's confirmation) a finished pilot submitted before it, less `_SUBMIT_SLACK_S` (`:338`, 60 s), is an earlier session's and left out of the verdict; one with no submit time counts. `_augment_provisioning` (`:381`) hands back the notice and the probe, so [[server]] `_ensure_endpoint_up` records a pilot that ran and died (`ShapeRuntime.dead_pilot`); `_augment_provisioning_notice` and `_pilot_status_over_login` keep their old shapes. A stop that met a dead pilot reads the probe too: the release lists live jobs only (PBS's `qstat -f` omits finished ones), and a replacement can come and die between two stops. `_released_jobs` (`:111`) reads the jobs a confirmed release cancelled, and `_NO_PILOT_YET` (`:108`) marks an unconfirmed release whose last look did read the scheduler, as opposed to a cold channel.

It also recognises a scheduler job the agent submits **by hand**: `_scheduler_submission` (`:740`) returns `sbatch`/`qsub`/`salloc`/`srun` when a command starts a NEW job (`inside_job=True` on the compute shape, where `srun` is a step of the block's own job; `srun --jobid` is a step anywhere), and `_submission` (`:759`) adds what the exit code can say — how many submit calls the line makes, and whether the line's exit code is the one call's own answer (`own_exit`: its last command, run directly — not under `timeout`/`xargs`/`bash -c` — and not waiting for the job, `_waits`) — for `_submission_refused` (`:776`, which also wants no job receipt, `_RECEIPT`). `_lex` (`:483`) is a one-pass, linear-time lexer: quotes removed, comments and here-document bodies dropped (a `<<EOF` inside quotes or a comment is not one), command substitutions cut out (`_subst_end` is quote-aware: `$(echo ")")`) and read at a capped depth (`_MAX_DEPTH`); `_group` (`:579`) leaves out a function body defined in the command and the patterns of a `case` (after `;;`, `*/qsub)` is a pattern); `_submit_call` (`:692`) walks past keywords, `VAR=…`, redirections and wrappers with their own arguments (`_past_wrapper`: `timeout -s KILL 60`, `nice -n 10`, `env -u X`, `xargs -n1`, `sudo -u`; `command -v` only among command's own options), into `bash -c`, `eval` and `find -exec`; `_starts_job` (`:671`) reads the scheduler's own options only before the first positional word (`_leading_options` knows which take a value), so `srun python --version` still submits, and `--help`/`--version`/`--test-only` (Slurm's `-h`/`-V` too; not PBS's, where `qsub -h` holds a job it still submits) are queries. Pure and precision-first; `server._detect_submission` calls it. Its cases live in `tests/submission_corpus.py`, shared with the harness grader.

Split step 6 (2026-09-03). The first step that needed **injection**: these ops run commands through `run_shell(shape="login")`, which lives in [[server]]; importing it back would be a cycle, so the login-shape channel is a parameter (`run_login`) that `server._login_runner(app)` builds at call time. Tests that patch `server._run_shell` therefore still reach every op; tests that patch the release call patch `scheduler_ops._release_blocks_over_login`. The harness keeps a DELIBERATE copy of `_release_cmd` (see [[Review 2026-09-03 — code quality]] D11) pinned by a test to the same marker scoping.
