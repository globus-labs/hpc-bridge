# ledger.py

> [!abstract] Role
> The durable batch ledger: SQLite at `<state_dir>/ledger.sqlite3` (0600, WAL, a busy timeout) beside [[state]]'s stores — the rows and the command of each batch, every attempt with its Globus task id and settlement, the lease that makes one server the batch's only admitter and collector, the retired block configs, and the interactive task ids `poll_task` answers after a restart. Design: [[Batch and swarm execution]] §4.

## What it does

- **`Ledger.open(state_dir)`** refuses a network filesystem by its type (`fs_type`: `/proc/self/mounts` on Linux, `mount(8)` on macOS; nfs, lustre, gpfs, cifs, smb, fuse… — `NetworkFilesystemError`, naming `HPC_BRIDGE_STATE_DIR`): WAL needs one host's mmap and locks, and the state dir is on NFS / Lustre / GPFS on login nodes and beside loam.
- **Tables:** `batch` (command, `task_walltime_s`, `results_dir` — the base; each batch writes in `<results_dir>/<batch id>/` — `idempotent`, `capacity`, `state`, `pause_reason`, `uec_hash`, `task_group_id` (the latest), `blocks_seen`, the lease's `owner_host` / `owner_pid` / `owner_start` / `heartbeat`, `cancel_requested`, `want_at` — its last refused ask for a slot of the block's window); `task` (one row per batch row: `row_json`, `attempt`, `state`, `task_id`, `sent_job` (the block job it was sent to), `sent_uec` (the config it went out with), `unknown_since` / `unheld` (a submit of unknown fate holds the stop from its failure until evidence — `unknown_holding`), `admitted_at`, `started_at`, `settled_at`, `rc`, `tail`, `stderr_tail`, `stdout_path`, `stdout_bytes`, `truncated`, `job_id`, `host`, `workers`, `remaining_s`, `settled_by`, `evidence`); `tgroup` (EVERY task group the batch's runners were minted: reconciliation reads them all — `add_task_group`, `task_groups`); `retired` (endpoint, config hash, why); `itask` (interactive task ids); `event` (append-only). A ledger from an earlier build gets the new columns on open. The command's text is stored — a replay record needs it, unlike `sent-checks`, which never holds one.
- **`reserve(batch_id, owner, n, uec_hash=…)`** — THE admission point: in one `BEGIN IMMEDIATE` transaction, the lease holder, the retired configs and the free window slots (`in_flight` + `submit_unknown` + `presumed_lost` hold one) are checked, and the lowest backlog rows move to `in_flight` with their next attempt, on the block `uec_hash` names (`sent_uec`, set here). `NotLeaseHolder`, `RetiredConfig`.
  - **The window is the block's** (the demo of 2026-11-03): the free slots are the block's window less the batch's own rows out AND the other batches' rows that can still hold a worker of this block (same `endpoint_id`, `coalesce(sent_uec, batch.uec_hash)`) — several batches on one block can no longer overfill its workers and leave tasks at the interchange. The block's window is the SMALLEST of: the block's own learnt worker count less one (`block_workers`, `learn_workers` — what a check or a task on it reported, kept per endpoint, config and block job, so it outlives the batch that learnt it; round 2) and the `capacity` of every batch with rows holding the block or admitting on it (rounds 1–2: a batch that had not learnt the count, and later one whose learner was drained, overfilled the block).
  - **What holds a slot** (`_on_block`, one scan on the partial index `task_holding_by_uec`; review round 1: an aborted batch's presumed-lost rows had shrunk every later window on a MEP's one config hash, for good). Never undercount a row that can still occupy a worker of the block in front; never hold one silently:
    - `in_flight`: while its batch's server runs (`holder_alive`; the caller's own server only when its start time matches — round 2: a restarted server handed the dead one's pid had held that server's rows for good); a gone server's only until `task_walltime_s` + `HOLD_MARGIN_S` past its admission ([[batch]] `HOLD_MARGIN_S`: the wrapper's own worst case past `task_walltime_s` plus a delivery allowance);
    - `submit_unknown`: until EVIDENCE says its task can no longer run (`unheld`, [[batch]] `_unknown_evidence`) or reconciliation settles it, whatever its batch's state or server (round 2's ruling, the codebase's own rule: the failed POST may have queued it, and on a MEP the next submit with its config delivers it);
    - `presumed_lost`: only while its server runs AND it was sent to the block in front (`sent_job` = the caller's `block_job`).
    - `reserve`'s answer (`Reserved.holders`) names the batches holding the block when they refused the caller slots; [[batch]] says so in its answer (`status(id)`, `cancel(id, 'abort')`). `block_holders` reads the same count.
  - **Fairness:** a batch refused slots by the OTHER rows on the block stamps `want_at` — never one refused by its own rows or the window, nor one refused only by fairness (so two waiters never defer to each other). While another batch on the block is still `admitting`, has a backlog, stamped `want_at` within `WANT_FRESH_S` (30 s, past an idle loop's 10 s pass) and could take a slot now (its own room: the window less its own rows less the others' on the block), a slot goes first to the batch ranked lower by ONE order whoever reads it: its rows in flight or of unknown fate on the block, then its last admission, then its id (round 2: a per-reader count had let two waiters each defer to the other). A huge batch cannot take back every slot it frees, and a waiter that stopped asking holds nothing back past `WANT_FRESH_S`.
- **Batch row sizing** (PR 2; [[sizing]]): `batch` gains each row's `cores`, `memory_mb` (resolved at admission when defaulted), `gpus`, `concurrency`, `pin`, `pilot`, `sized` (the call gave a size: nothing is admitted before the block is measured), `sizing_defaulted` and a `proposal`; `task` gains what each attempt holds (`req_cores`, `req_memory_mb`, `req_gpus`, set by `reserve`, so a resize never changes what is out), its own use (`peak_rss_kb`, `cpu_s`, `wall_s`, `nproc`, `cpus`, `gpu_ids`, `why`, `threads`, `oom_kills`) and `not_before` (a row a busy slot sent back waits). A new table `block_measure` keeps each block's measure (`learn_measure` / `block_measure`, keyed as `block_workers`). **`reserve` admits a sized batch against the block's measured pool** (`_pool`, `_on_block_use`, `_fits`): the CPUs, memory (the limit less the pool's idle use), GPUs and rows (the workers less the interactive one, at most `WIDTH_CAP`) that every batch's holding rows hold, against the batch's own capacity and concurrency; the fairness order is PR 1's, each waiting peer's room counted in its own row size. **A reservation for the head waiter** (review F7): while a batch ranked first waits with a row that fits the whole pool but not what is free — big rows behind small ones, a pilot wanting the whole block — the others admit only beyond that row's need, so it starts as soon as enough rows settle (a freed CPU going to a small row each time had starved it). Each attempt also records `req_mem_default` (its memory was the default share: a kill at it asks — F6) and `pinned` (the wrapper's own word — W8); a pilot keeps the user's size in `pilot_saved` while it holds the whole block. A batch with no size, or a block with no measure, keeps PR 1's window.
- **`take_lease`** — refreshed by the holder; taken over only when the heartbeat is stale (`LEASE_STALE_S`, 30 s) AND the holder is gone (`holder_alive`): its pid dead (`pid_alive`, a seam), or alive but started at another time than the record says (`proc_start`: Linux's `/proc/<pid>/stat` starttime, else `ps -o lstart=` under `LC_ALL=C TZ=UTC0`, so every reader renders it alike) — a pid the OS handed on does not hold a dead server's lease (L7). A start recorded in another form, or unreadable now, is no evidence: a live pid's lease is never taken on it (round 2: the reader's TZ and locale had changed the string). The hostname is not consulted: the ledger is on this machine's local disk, and macOS renames itself on a new network (a dead holder under the old name had held its lease for good).
- **Batch phase 2a tables** ([[jobs]], [[meter]]):
  - **`envelope`:** cap, unit, facility, account, the dimensions (`max_jobs`, `max_nodes_per_block`, `accounts`, `partitions`), deadline and `at_deadline`, `site_backstop`, `approved_by` (the session) with `owner_host` / `owner_pid` / `owner_start`, `state` (`open | exhausted | draining | closed`), the meter's `spent`, `committed`, `unledgered` and `unledgered_hold`, and `excluded` (the jobs the user said are not theirs to count).
  - **`job`:** `source` (`submit_job | adopt | pool_block`), `native_id`, size, `tasks`, `array_spec`, `throttle`, `rate`, `min_charge_h`, `worst_case`, `script_path` / `script_hash`, `deadline`, `state` (live: `reserved | submit_unknown | held | queued | running`; ended: `done | failed | cancelled | refused`), the meter's `charged`, `committed`, `meter_source`, `array_counts`, and (fix round 1) `cancel_requested` (a stop or cancel asked an admission in flight to give up), `unheld` (a hand submit the hold could not catch: never cancelled by hpc-bridge on its own) and `hand` (the hand submit that adopted it).
  - **`hand`:** a gated hand submit in flight (`token`, `envelope_id`, `facility`, `session`, `mark_path` — since round 3 its `after` snapshot file in `<session dir>/hands/<token>/`; `shim_dir` and `before` are unused since the hold went —, `state` `open | closed | gone`, `note`), written before its command is sent (`add_hand`, `hands`, `update_hand`), so the next call adopts what it submitted whatever became of the call.
  - **`meter_reading`:** one row per tick per envelope.
- **`reserve_job`** is the envelope's admission point, in one `BEGIN IMMEDIATE` transaction. It checks that the envelope admits (open or exhausted, this session's, before its deadline), the job's dimensions, and that the hold (`job_hold`: a job's worst case until it is metered, then charged + committed; plus the unledgered jobs) plus the job's worst case stays within the cap. Then it inserts the job. It raises `EnvelopeExhausted`, `EnvelopeNotOwned`, `EnvelopeClosed` or `EnvelopeLimit`. `ignore_owner` skips every check: a job that is already the user's (a held one a dead server left, an unheld hand submit counted over the cap). `move_job(job_id, only_from=, unless_cancel=, while_admitting=)` moves a row only from those states, only if no cancel was asked, and (with `while_admitting`) only while its envelope still admits — a stop closes admission first — in one transaction (a stop and an admission cannot both win). A hand row's `handle` is the command's exit-status file once it was sent.
- **The ceiling** (`HPC_BRIDGE_ENVELOPE_MAX`): `add_envelope(…, ceiling=)`, `set_cap(…, ceiling=)` and `rebind_envelope(…, ceiling=)` check the sum of the open caps on the facility for every account the envelope admits (`envelope_accounts`, `_ceiling_check`) inside their own transaction (`EnvelopeCeiling`, review B7). `rebind_envelope` is a later session's yes, and `exclude_jobs` / `excluded_jobs` record "not mine".
- **`settle(…, only_from=…)`** — moves one attempt's row (its CURRENT attempt only) to a state, with its result fields.
- **`retire` / `unretire`** — a stop or a reap retires the block's config (on SSH its `hpcb_block` token makes it unique: S5 saw one stray submit with a retired config restart the user endpoint and a block within 18 s); the user's yes on a resume lifts it.

> [!warning] Only the lease holder admits or collects
> Two servers on one task group swallow each other's results (S1), and two admitters double the window. Every admission goes through `reserve`, which re-checks the lease inside its transaction; a server that loses the lease drops the batch from its process and only reads it.
