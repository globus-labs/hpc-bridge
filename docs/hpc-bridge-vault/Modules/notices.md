# notices

> [!abstract] Role
> Every pure agent-facing text builder and result factory in one module: the first-contact explanations (`_explain_provision_error`: NO SSH ACCESS / CANNOT REACH / REMOTE FILESYSTEM), the spend floor (`_spend_floor_guidance`, used by both `ensure_endpoint_up` and `run_shell`/`reset_session`; `_reap_prefix`, why spend is asked again: a reap, or a partition/account switch whose reason `_switch_reason` writes — the old terms and the old block's fate, which on a facility endpoint uses #178's words), the account floor (`_needs_account_notice`: where an SSH user finds an account — connect_facility's allocations, the login shape — and a facility endpoint's user the facility's tool or portal), the connect's one clause when an env preset was not applied (`_unapplied_presets_note`), the warm-block bounds note, the Globus-login instructions (`_login_notice`, `_needs_login_result`), the pre-auth hand-off, the terminal refusals (`_no_account_notice`, the transient-conflict classifier and dispatch-error suffix), the no-facility notice (`_no_facility_notice`: the one "No facility connected" text that `login_shell`, `run_shell`, `reset_session` and `ensure_endpoint_up` share, which names a connect that only proposed a config, or one waiting on a one-time login), the facility no-cancel notice (`_no_cancel_notice`, [#178](https://github.com/globus-labs/hpc-bridge/issues/178): a MEP stop's or detach's text, which leads with "NO CANCEL WAS ISSUED" and names each block left billing — its scheduler job, the latest it can bill until as a clock time (`_clock_time`), and the user's own cancel and check commands per scheduler (`_SCHEDULER_CMDS`: `scancel`/`squeue`, `qdel`/`qstat`, `bkill`/`bjobs`), with `squeue -u <the mapped account>` and how Globus Compute names a block — a prefix every Globus Compute block on a shared account shares, so check the start time and partition (`_PARSL_NAME_NOTE`) — when no job id is known — plus the `EndpointStatus` fields it implies: `_left_spend_stopped`, `_left_block_state`, `_left_job`; the five-minute still-allocating notice `_allocating_notice` names a block of the same partition and the mapped account, with a cancel command only for a `job_verified` one), the hand-submission note (`_scheduler_submit_notice`, applied by `_with_submission_notice` to run_shell's and poll_task's results (login_shell's directly): a job submitted from the login node or from inside a block bills the allocation, is not tracked or cancelled by hpc-bridge, and is the user's to confirm — worded for what the result shows: refused only when the exit code is the line's one submit call's own answer and no job receipt was printed (`scheduler_ops._submission_refused`), else submitted / may have submitted / still running / finished), and the `ShellOutcome` factories (cold, needs_confirmation, busy, running — whose long-work advice is checkpoint/resume, or a batch job only with the user's spend confirmation — past-ceiling, orphaned, error, shape-reject, released-under-the-call, never-sent, no-facility). The busy and running factories say when a task came from a call the client cancelled (`_CLIENT_CANCELLED`), because the agent never received that task id.

Split step 3 (2026-09-03). A notice IS the product — the agent reads it and acts, and the harness graders key on some phrases (`NO ACCOUNT`, `not confirmed`, `ORPHANED`) — so the words live in one place. No I/O and no state mutation here: a builder reads [[context]] / [[config]] and returns text or a model. [[server]] re-exports every name, so tests that import `server._explain_provision_error` keep working; none of these is monkeypatched.
