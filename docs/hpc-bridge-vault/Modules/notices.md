# notices

> [!abstract] Role
> Every pure agent-facing text builder and result factory in one module: the first-contact explanations (`_explain_provision_error`: NO SSH ACCESS / CANNOT REACH / REMOTE FILESYSTEM), the spend terms (`_block_terms` (`notices.py:200`): the `BlockTerms` of the block a runtime would start — only what the facility receives (`_wire_keys` (`:174`): a facility endpoint's `key_map` and schema filter, `dispatch_uec`; a dropped partition/account/node count reads as the facility's own default), queue and account each with its source: `named` (this call) → `this_call`, `AppCtx.compute_choice` → `earlier_call` (a runtime seeded after a stop carries it too), else the binding's `AppCtx.terms_origin` (`registry` / `env` / `byo_details` / `discovered`), `facility_template` when nothing is sent; a configured account is only ever the preset (`env`), none is `none_needed` only where the registry says so and the facility agrees; `_dropped_term_notice` (`:187`) refuses a partition or account the facility would drop; `_terms_line` (`:269`), the one sentence every spend answer and connect lead with — queue and account first, "queue" on PBS (`_queue_word`, also in `_terms` for a re-ask), then the registry's account hint as its own quoted sentence where an account is missing (`_hint_sentence`), and on a facility endpoint what compute-only means for spend; `_connect_terms_note` (`:297`), connect's one question — only for what is unsaid, a preset counting as said — whose yes is the spend confirmation, sent with the answer in one ensure_endpoint_up call; with nothing to ask, a one-line statement and the start; with no terms, a static instruction), the spend floor (`_spend_floor_guidance`, used by both `ensure_endpoint_up` and `run_shell`/`reset_session`; with no account where one is needed, it asks for it and sends it in the same confirming call; `_reask_prefix`, why spend is asked again: a reap, or a partition/account switch — the old terms and the old block's fate (`_switch_fate`), or that the terms are back to the confirmed ones, naming a block a switch left only while a stop still would (`_still_left`); `_switch_receipt`, the same fate for a call that switched and confirmed at once; `_left_block_clause`, the words a reconnect (`connect._prior_note`) and a switch both use for a block a facility endpoint lets go of), the account floor (`_needs_account_notice`: led by the terms line, which carries the entry's `account_hint` (the ACCESS remark only without one); where an SSH user finds an account — connect_facility's allocations, the login shape — and a facility endpoint's user the facility's tool or portal; `_needs_confirmation_outcome` / `_needs_account_outcome` give run_shell the same `block` and the same head as ensure_endpoint_up), the connect's one clause when an env preset was not used (`_unapplied_presets_note`: another facility than the one `HPC_BRIDGE_MACHINE` names; the partition preset on a facility endpoint, or under a partition given in `details=`), the warm-block bounds note, the Globus-login instructions (`_login_notice`, with the reason a login is needed when it is known; `_needs_login_result`), the bare `hpc-bridge error: <type>: <text>` (`_hpc_bridge_error`, shared by `_error_outcome`, `ensure_endpoint_up`'s provision failure and the MEP attach's: a dead Globus login gets its remedy instead of the raw token-endpoint tuple), the dead-login notice (`_login_expired_notice`: the stored Globus login no longer works, not a queue wait and not the config — `authenticate(force=True)`; `ensure_endpoint_up` returns it as `provisioning`, never a `down` that could hide a block still billing, and `_cold_outcome` as `failed`), the pre-auth hand-off, the terminal refusals (`_no_account_notice`, the transient-conflict classifier and dispatch-error suffix), the no-facility notice (`_no_facility_notice`: the one "No facility connected" text that `login_shell`, `run_shell`, `reset_session` and `ensure_endpoint_up` share, which names a connect that only proposed a config, or one waiting on a one-time login), the facility no-cancel notice (`_no_cancel_notice`, [#178](https://github.com/globus-labs/hpc-bridge/issues/178): a MEP stop's or detach's text, which leads with "NO CANCEL WAS ISSUED" and names each block left billing — its scheduler job, the latest it can bill until as a clock time (`_clock_time`), and the user's own cancel and check commands per scheduler (`_SCHEDULER_CMDS`: `scancel`/`squeue`, `qdel`/`qstat`, `bkill`/`bjobs`), with `squeue -u <the mapped account>` and how Globus Compute names a block — a prefix every Globus Compute block on a shared account shares, so check the start time and partition (`_PARSL_NAME_NOTE`) — when no job id is known — plus the `EndpointStatus` fields it implies: `_left_spend_stopped`, `_left_block_state`, `_left_job`; the five-minute still-allocating notice `_allocating_notice` names a block of the same partition and the mapped account, with a cancel command only for a `job_verified` one), the SSH stop's answers by its evidence (`_stop_down_notice` (`:718`): the `down` — what settled it: nothing to cancel after a REJECTED submission (`_rejected_stop_notice` (`:626`): no block was created), a check of ours the endpoint gave up — naming a pilot that died before it ran it, with its exit status —, a check the service still lists as queued whose own user endpoint received it, failed it with bad state and stopped for good (`_lost_checks_words` (`:697`): that user endpoint by name, when its bad state was logged, that nothing of it runs and the endpoint has not started it again, so no block of ours can start for it, and that its report of the failure was lost on the endpoint's side — a known globus-compute-endpoint race —, which is why the service still lists it), or a block that ran our last check during the stop and was cancelled; `_check_pending_notice` (`:662`): the `draining` while a check of ours is still queued on the endpoint, which can start a block to run it — which check (its terms by `_check_words` (`:647`), its task id), a pilot that died before it, that its state could not be read, how long this stop waited, what kept the stop's look on the login node from settling it (`looked`), call again in about a minute, `teardown_endpoint` ends one that stays queued; never "still being submitted", never idle-release as its backstop; `_failed_release_notice`: a release whose scheduler command failed or refused a cancel, quoted, never "cold"; `_rejected_switch_note` (`:427`): the call that switched, confirmed and met a rejection says what became of the old block, not a receipt for a new one; `_reask_prefix` also says a re-ask follows a rejected submission (`ShapeRuntime.rejected`) and that the same terms are refused again), the hand-submission note (`_scheduler_submit_notice`, applied by `_with_submission_notice` to run_shell's and poll_task's results (login_shell's directly): a job submitted from the login node or from inside a block bills the allocation, is not tracked or cancelled by hpc-bridge, and is the user's to confirm — worded for what the result shows: refused only when the exit code is the line's one submit call's own answer and no job receipt was printed (`scheduler_ops._submission_refused`), else submitted / may have submitted / still running / finished), and the `ShellOutcome` factories (cold, needs_confirmation, busy, running — whose long-work advice is checkpoint/resume, or a batch job only with the user's spend confirmation — past-ceiling, orphaned, error, shape-reject, released-under-the-call, never-sent, no-facility). The busy and running factories say when a task came from a call the client cancelled (`_CLIENT_CANCELLED`), because the agent never received that task id.

Split step 3 (2026-09-03). A notice IS the product — the agent reads it and acts, and the harness graders key on some phrases (`NO ACCOUNT`, `not confirmed`, `ORPHANED`) — so the words live in one place. No I/O and no state mutation here: a builder reads [[context]] / [[config]] and returns text or a model. [[server]] re-exports every name, so tests that import `server._explain_provision_error` keep working; none of these is monkeypatched.
