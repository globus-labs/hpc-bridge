# binding

> [!abstract] Role
> How a machine is REACHED: build the `Facility` for a catalog entry (`_facility_from_entry` → an SSH `SlurmFacility` with login name from `~/.ssh/config`, key, ControlMaster and login-node pin, or a `MEPFacility`), the runtime catalog (`make_catalog` → the public registry, read anonymously unless a Search-scoped login exists), the startup-pin path (`make_facility`, `_catalog_facility`), the no-facility default (`_default_local_facility`), the session/BYO helpers (`_entry_from_details`, `_session_endpoint_name`, `_facility_store`, `_resolve_scratch_root`).

Split step 5 (2026-09-03). **The patch-target rule:** every caller — in [[server]] and in this module — goes through the owning module's attribute (`binding.make_catalog()`, `binding._facility_from_entry(…)`, `config._control_settings()`), and tests patch `binding.<name>` / `config._control_settings`, never `server.<name>`. Re-exports from `server` remain for imports only. This is the trap the code-quality review warned about: a name re-exported from `server` but patched there does not reach a caller that resolved it elsewhere.

**The env presets apply to one facility.** `HPC_BRIDGE_ACCOUNT` and `HPC_BRIDGE_PARTITION` belong to the facility `HPC_BRIDGE_MACHINE` names: by id or subject (`config.names_machine`), or by an alias the startup pin resolved (`_catalog_facility` records it in `_PINNED`; `_names_machine`). `_facility_from_entry` applies the partition preset only to the entry named (the startup pin's included, since `_catalog_facility` records its resolution first), never over a bring-your-own entry's own partition (`facility_key == SESSION_KEY`). The account is its caller's choice: `_catalog_facility`'s `_require_env("HPC_BRIDGE_ACCOUNT")` is unchanged, and [[connect]] passes the preset only for the named machine. A facility MEP never took the partition preset (its defaults are the entry's). `_partition_preset(entry)` is that rule in one place, and `_terms_origin(entry, discovered=…)` (`binding.py:114`) records where the default terms come from for BlockTerms' sources ([[models]]): `registry`, `env` (the partition preset applied), or for a bring-your-own entry `byo_details` / `discovered`; the entry's `account_required` as the registry's claim (None for your own) and its `account_hint`. The startup pin keeps its origin in `_PINNED_ORIGIN` (only a pin that succeeded) for `server.lifespan`. `_entry_from_details` first writes the details' `scheduler_options` as the submit script will carry them (`_directive_details`, on `catalog.entry.directive_lines`, 2026-10-16 `polaris_filesystems`): parsl writes them into the header verbatim, so a line that starts with `-` — an option written bare, as a site's comment quotes it ("e.g. -l filesystems=…") — gets the scheduler's prefix (`DIRECTIVE_PREFIX`: `#PBS `, `#SBATCH `); a line of THIS scheduler's directive (its prefix and a space or tab at the line's start) is kept as given, and an indented one — a comment to the scheduler — is unindented as a rewrite; a plain comment (`#`, `# …`) is kept; a blank line is dropped; any other line is refused (`SchedulerOptionsError`): a shell command (in the script it runs, and the scheduler stops reading directives at it — on Slurm parsl writes the partition and account directives after it), another batch system's directive word (sbatch reads `#SLURM` as its own and translates `#PBS` and `#BSUB` after its own pass, so they override; `#SBATCH` does nothing on PBS), a directive with no space after its word (`#SBATCH-A x`), a `#!` or `#word` line (review round 2, T3). `_directive_details` returns each rewrite, (given, written), which [[connect]] reports (each line cut at 120); written details give none. Then it refuses a `scheduler_options` that sets one of the block's terms — read on the WRITTEN lines, so `-A x` is the `#PBS -A x` it becomes, and on the refused lines first (a `#PBS -A` on Slurm is refused for the account) — with a `TermsDirectiveError` (a `SchedulerOptionsError`; `_terms_refusal`): the account and the partition/queue, and since round 2 (T4) the walltime and the node count, which parsl writes BEFORE scheduler_options and a later directive overrides (`catalog.entry.scheduler_terms_kind`: under any of `#SBATCH`/`#SLURM`/`#PBS`/`#BSUB`, with or without a space after the word — Slurm's `-A/--account/-p/--partition` by any prefix sbatch accepts, `-N/--nodes`, `-t/--time`, short flags in a bundle; PBS's `-A`, `-q` and a `-l` list naming walltime, select, nodes or nodect; LSF's `-q`, `-P`, `-W`, `-n`). Sent, it would charge or size what the block's terms never show. Two more kinds are refused the same way since round 3 (#3): the pilot's own files — Slurm `-o/--output` (kind `output`: parsl writes it in the pilot's user endpoint directory, the path squeue's StdOut shows — `_release_cmd` cancels by it and the probe finds the pilot by it, so another path meant a stop that answered "released none" while the pilot held or billed) and `-e/--error` (kind `error`, its own reason since round 4, #5: the release reads StdOut only, so another error file loses just what the probe reads there, why a dead pilot exited; hpc-bridge has no setting that moves the endpoint's directory, and the refusal says so rather than point at one); PBS `-o/-e` stay, its record keeps the marker in Submit_arguments — and an array (Slurm `-a/--array`, PBS `-J`: several blocks behind one spend question). A PBS `-l select=…` is refused as the node count, with `_select_words` pointing at `select_options` (round 3, #1: the ban had left a GPU site no way to ask for resources). `catalog.entry.select_advice` works the line out (`SelectAdvice`): the one chunk's resources as `select_options`, its ncpus as `cpus_per_node` (with none, the words add that `cpus_per_node` is needed, or parsl's chunk asks for `ncpus=1`; round 4, #9), and whatever else the line names — another `-l` item (`filesystems=home:eagle` beside the select) or list, another option — as `rest`, a `#PBS …` line of its own that the refusal says to keep and `_accepted_details` keeps (round 4, #3: both had dropped it, and a Polaris-style hook would hold the pilot); a rest that sets a term too (a second select, a walltime) gets no conversion. `_terms_refusal` takes the facility's scheduler: on Slurm (sbatch translates a `#PBS` line) a select is pointed at an `#SBATCH` directive (`--gres=gpu:<ngpus>`, the ngpus read from the line itself, whatever `select_advice` makes of it; round 5, N4), never at the PBS-only `select_options` (round 4, #4). A refused line's term is named only where the scheduler still reads it as a directive (`catalog.entry.read_as_directive`: sbatch reads `#SBATCH`/`#SLURM` and translates `#PBS`/`#BSUB`; qsub reads `#PBS` alone), so on PBS an `#SBATCH --output=…` is refused as not this scheduler's directive, not for a Slurm term (round 5); the ingest reads refused lines the same way. `FacilityDetails.select_options` — PBS only, checked by `catalog.entry.select_options_problem` (name=value pairs joined by ":", no chunk count, no "+", no select/ncpus/walltime/nodes/place/account/queue) — becomes the session entry's `Defaults.select_options`, the profile's, and [[facility-remote]]'s PBS template renders it into `PBSProProvider(select_options=…)`, which parsl appends to its own `select=<nodes>:ncpus=<cpus_per_node>`; the node count stays the block's. `_accepted_details` offers a cached one-chunk `select=1:…` line (PBS) back as `select_options` (and its ncpus as `cpus_per_node`, the rest of the line as its own line). `_accepted_details` is the lenient twin for a cached record: every refused line left out, each with its reason, for [[connect]]'s proposal. A bring-your-own entry (`_entry_from_details`) carries `account_required=False`: nothing curated says its scheduler enforces accounting, so the account floor stays off there, as before; a registry SSH entry's flag reaches its `SlurmFacility` ([[facility-remote]]).

**The no-facility default.** With no `HPC_BRIDGE_MACHINE`, `make_facility` (`:165`) returns `_default_local_facility()` (`:154`), and `lifespan` uses the same builder, with `unbound=True`, when a pin fails at boot. It is a [[facility-local|`LocalFacility`]] marked `implicit` (nothing chose it) unless `HPC_BRIDGE_ENDPOINT_ID` is set — the only local-dev path, an endpoint the user runs ([[Configuration]]) — and always after a failed pin. [[server]] then refuses every call that would stand up or use an endpoint with "No facility connected" (`context._no_facility_bound`), so the agent connects a facility instead of getting a local endpoint on the MCP host.
