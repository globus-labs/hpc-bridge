# models.py

> [!abstract] Role
> The Pydantic result types the MCP tools return. Failures come back as **structured outcomes**, never raw crashes.

## What it does

- **`ShellOutcome`** (`models.py:11`) — result of `run_shell`/`reset_session`/`poll_task`: `phase` (`complete` | `cold_start` | `failed` | `needs_confirmation` | `running`), `exit_code`, `stdout`, `stderr_snippet`, `block_state`, `session_spend`, `task_id`, `notice`. `running` = the command outlived the sync-wait and is still executing (**not** cut) — `task_id` is the handle for `poll_task` ([#21](https://github.com/globus-labs/hpc-bridge/issues/21)). In a `complete` outcome — the only one carrying command output — the agent receives each too-long `stdout`/`stderr_snippet` cut to its end, opening with a marker saying what was dropped, and a `notice` saying how to read the whole output ([[dispatch]] `for_agent`); hpc-bridge's own consumers read it uncut. A `failed` outcome's `stderr_snippet` is exception text, bounded at the source to its head and tail (`_error_text`). A result over Compute's size limit is `failed` with `exit_code=None` (unknown); its private `_worker_answered` keeps [[warmth]] from voiding the block's liveness.
- **`EndpointStatus`** (`:32`) — result of `ensure_endpoint_up`/`stop_endpoint`/`teardown_endpoint`: `status` (`up` | `provisioning` | `down` | `draining` | `needs_confirmation` | `tearing_down` — teardown's login-node ops outlived one call's wait and run on in `AppCtx.teardown_task`; call again to confirm), `block_state`, `endpoint_id`, `session_spend`, `partition`, `account`, `notice`. `draining` = stop dispatched the block cancel but couldn't confirm it (a cold release channel) — honest, never a false `down` ([[Cost control]], [#24](https://github.com/globus-labs/hpc-bridge/issues/24)); on a facility MEP `draining` is *terminal* (no cancel channel). A `down` from `ensure_endpoint_up` with a `NO ACCOUNT …` notice is the terminal identity-mapping refusal ([[facility-mep]]).
- **`LoginShellResult`** (`:57`) — result of `login_shell`: `exit_code`, `stdout`, `stderr_snippet`, `notice` — a separate channel from compute (no block, no spend). Its streams reach the agent cut the same way (`for_agent`).
- **`AllocationOption`** (`:67`) — one allocation the user could charge to: `account` (becomes the provider's `account`), `balance`, `units`, `type`.
- **`ConnectFacilityResult`** (`:165`) — result of `connect_facility`: `phase` (`needs_account` | `provisioning` | `needs_facility_details` | `proposed_facility_details` | `needs_preauth` | **`needs_login`** | `unsupported` | `failed`), `facility`, `reused` (True when the connect reattached to an already-online endpoint — a zero-SSH reconnect, [[Standing up the endpoint]], [#20](https://github.com/globus-labs/hpc-bridge/issues/20) — and always True for a facility MEP attach), `allocations` (`AllocationOption`s — empty on a MEP or a facility with no listing), `preauth_command` (the `ssh -fN …` line the **user** runs in their own terminal when `phase="needs_preauth"` — an MFA/password host; the secret never reaches the agent, [[MFA and interactive SSH auth]]), **`login_url`** + **`login_mode`** (`browser` | `paste`; set on `needs_login` — the Globus login gate, a phase not a prompt: in browser mode the loopback listener in the server receives the code, in paste mode the user hands a one-time code to `complete_login`; [[login]]), `proposed_details` (the discovered `FacilityDetails` draft, set on `proposed_facility_details`), `notice`. Drives the [[Facility catalog|catalog]] selection loop.
- **`LoginStatus`** (`:208`) — result of `authenticate` / `complete_login`: `phase` (`logged_in` | `needs_login` | `failed`), `login_url`, `login_mode`, `notice` — the same login shape as the connect result, as its own tool result.
- **`FacilityDetails`** (`:89`) — *input* to `connect_facility(details=…)` for a machine **not** in the catalog, **and** the discovery probe's *output* (a proposed draft). Its per-field `Field(description=…)` doubles as the question template (`ssh_host`, `interface`, `env_setup`, `scratch_root`, `partition`, `scheduler` (`slurm`/`pbs`), optional `cpus_per_node` + `scheduler_options` (PBS site directives, e.g. `#PBS -l filesystems=home:eagle`), an optional allocation command + parser, `walltime`, `amqp_port`, and optional `endpoint_name` / `display_name` — normally left unset so the endpoint is keyed on the SSH host). Facility config only — SSH credentials come from `~/.ssh/config` (env overrides optional), not here. See [[Globus index discovery channel]].

The `needs_confirmation` phase/status is the [[Resource shapes & the spend floor|spend floor]] signal; `cold_start` is the no-hang cold path; `running` is a long task's poll handle ([[The MCP tools|poll_task]]) and a `failed` saying ORPHANED is that handle's endpoint having gone away; `needs_login` is the Globus login gate; `proposed_facility_details` (a probed draft to confirm), `needs_facility_details` (no SSH host yet), and `needs_preauth` (the host needs an interactive login) are the un-indexed-facility signals.
