# warmth

> [!abstract] Role
> The per-shape warmth state machine — Executor build/reuse (`_runner_for`), the canary that proves a worker is live (`_confirm_worker`: TTL, live-task shortcut, non-timeout failures → `runner_stale`, the sticky NO ACCOUNT verdict, the transient-conflict count), the spend floor and partition/account application (`_provision`, `_apply_partition`, `_apply_account`), and dropping shapes (`_drop_compute_shape`, `_drop_all_shapes`, `_forget_identity_verdicts`). Task-handle bookkeeping lives here too (`_register_task`, `_resolve_task`, `_busy_session`, `_live_task_handles`, `_drain_shape_tasks`, `_endpoint_gone`) because a live task IS a warmth signal the runner rebuild and the canary consult.

Split steps 7–8 (2026-09-03; the review planned `warmth` and `tasks` separately — their coupling made one module the honest cut). Every function runs under `app.lock`, held by the caller in [[server]]. One exception: a cancelled call registers its still-running command (`_register_task(..., client_cancelled=True)`) in a single synchronous step without the lock, because a cancelled call must not wait for it, and code with no await cannot interleave with any other call. A live handle of that kind is like any other: the canary short-circuits on it, `_presumed_reaped` will not presume the block gone, `_busy_session` refuses its session, and partition/account switches are refused. A handle pending past its ceiling (`_past_ceiling`) still counts as live, because it may only be queued. `_overdue` (past its ceiling plus `_LOST_TASK_GRACE_S`) is consulted only by a facility MEP's stop and detach (`server._block_work`). `_runner_for` defers a credential-only swap while a call is in its sync-wait, as it does for a live handle. `_drop_compute_shape_locked` is the drop for a stop that must look and drop in one locked step. `_resolve_task` notes a result only on the runtime the task ran on, and only if that runtime is still current: it never rebuilds a dropped shape. Tests patch `warmth._provision` / `warmth._drop_compute_shape`; `server` calls those through the module.
