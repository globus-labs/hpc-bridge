# The MCP tools

> [!abstract] Role
> The agent-facing surface — **eleven** tools, all declared in [[server]], all returning structured [[models|Pydantic results]] (failures come back as outcomes, never raw crashes).

## Stand up & run

| Tool | Returns | What it does |
|---|---|---|
| `ensure_endpoint_up(shape="compute", partition=None, confirm_spend=False, account=None)` | `EndpointStatus` | Provision/probe the endpoint; reports `up` only once a **worker answers a canary** ([[Warmth, the canary & cold-start]]), else `provisioning` — whose notice carries the pilot's real scheduler state (queued / held / "no pilot → likely rejected", [#32](https://github.com/globus-labs/hpc-bridge/issues/32)) or the last dispatch failure. A billed `compute` block won't start without `confirm_spend=True` → `needs_confirmation`. `partition` and `account` (the chosen allocation) select the **scheduler target** — a Slurm partition or PBS queue — and persist for the session (refused while a task is still running). On a facility MEP a refused identity mapping is a **terminal `down`** saying `NO ACCOUNT` and naming the identity — not a queue wait, don't poll ([[facility-mep]]). |
| `run_shell(command, session_id="default", shape="compute")` | `ShellOutcome` | Run a command on the warm block (`shape="compute"`) or the login node (`shape="login"`, free — the no-SSH discovery channel; **refused on a compute-only MEP**). Cold endpoint → `cold_start` (no hang). A command that outlives the sync-wait comes back `running` + a `task_id` (**not** cut — it runs up to the block walltime) → retrieve it with `poll_task`. cwd/env persist per session ([[Session continuity]]). |
| `poll_task(task_id, wait=0.0)` | `ShellOutcome` | Retrieve a long task's result: `complete` once it finishes, else `running` (poll again); `wait` optionally blocks up to N seconds. This is what lets long work be a *foreground task* instead of a detached process — a running task keeps the block busy, so it's never idle-released ([[Cost control]], [#21](https://github.com/globus-labs/hpc-bridge/issues/21)). A pending task whose endpoint is unbound or reports offline is **ORPHANED**: a terminal `failed` (stop polling; reconnect and re-run), never `running` forever ([#44](https://github.com/globus-labs/hpc-bridge/issues/44)). One still pending past its ceiling stays `running`, and its notice says it may be queued behind another task or a relaunching block, or lost (keep polling, or abandon it as its notice says for its shape: a login task does not hold stop, but holds its session and the login worker). On a facility MEP, once a compute task is well past its ceiling, it is presumed lost and no longer holds stop or the detach. |
| `reset_session(session_id="default", shape="compute")` | `ShellOutcome` | Clear a session's persisted cwd + environment (per shape). A session with a task still running is busy — reset (like a second `run_shell`) is refused until it's polled. A reset still queued past the sync-wait comes back `running` + a `task_id`, like `run_shell`. |
| `stop_endpoint()` | `EndpointStatus` | Release the billed block over the login endpoint (AMQP, no SSH) via the scheduler's own cancel (`scancel` on Slurm, `qdel` on PBS); **leave the login-node endpoint online** for a zero-SSH reconnect. "Stop" = stop spending, not tear down ([[Cost control]]). Retries a cold release channel to confirm; `status="down"` = cancel confirmed, `status="draining"` = dispatched but **unconfirmed** (re-call to confirm; [#24](https://github.com/globus-labs/hpc-bridge/issues/24)). On a facility MEP there is no cancel channel: `draining` is **final** (the facility's idle-release reclaims the block; the notice names the window). On either kind, stop is **refused** (`up`) while our work holds the block: a running task, a `run_shell` still in its sync-wait, or the command of a call the client cancelled (cancelling a call does not stop its command; `poll_task` it). |
| `teardown_endpoint()` | `EndpointStatus` | The explicit "destroy it entirely": `gce stop` + `delete` over SSH and clear all state — for when the user insists on removing the login endpoint (normally it's left online for reuse). After it, don't `run_shell` (that re-provisions a fresh one). On a facility MEP it only **detaches** (nothing of ours to destroy), and is refused like stop while our work holds the block. |
| `login_shell(command)` | `LoginShellResult` | Read-only command on the login node over a **fresh SSH** connection — the cold-start discovery escape hatch. Prefer `run_shell(shape="login")` once an endpoint is up ([[Discovery today]]). Requires a connected SSH facility; refused with a notice on a compute-only MEP (no SSH, no login node). |
| `authenticate(force=False, mode=None)` | `LoginStatus` | The Globus login gate as a tool: `logged_in` (also when the browser flow lands during the call's wait), or `needs_login` with a `login_url` — browser loopback flow (opens the browser, waits up to 90 s; the URL is returned to show only if no browser opened; single-use) or Globus's paste-back auth-code page when headless / `mode="paste"`. 10-min TTL; `force=True` re-consents. Minimum consent = the Compute SDK's endpoint floor; Search is not requested (registry reads are anonymous). |
| `complete_login(code)` | `LoginStatus` | Paste-back completion: exchanges the one-time auth code the user pasted from Globus's auth-code page and stores the tokens in the Compute SDK's `storage.db` under the SDK's own client id (the one the remote endpoint refreshes with). Refused once the attempt expired. Never a password. |

## Catalog selection (the agentic discovery front)

| Tool | Returns | What it does |
|---|---|---|
| `list_facilities(query="")` | `list[CatalogSummary]` | Browse the [[Facility catalog]] (the public registry, read anonymously — works with no config and no login). Agent-safe summaries — identity + provenance + **how you get in** (`access`: `mep` = zero SSH but the facility must have mapped your Globus identity; `ssh` = an account + key-based SSH on the login host; `access_note` spells it out; `scheduler`), **no** executable config or raw UUIDs. No SSH, no spend. |
| `connect_facility(facility, ssh_host=None, details=None)` | `ConnectFacilityResult` | **The entry point for reaching any facility.** **Gated on Globus login first** — before the catalog read or any SSH: in browser mode the call opens the browser and **waits up to 90 s (`HPC_BRIDGE_LOGIN_WAIT_S`) for the redirect, then continues in the same call**; only a still-open, headless or paste login returns `needs_login` (see `authenticate`). Then it resolves the entry — explicit `details=` → **the registry** → the local BYO cache → probe ([[Facility catalog]]) — and binds it. **SSH entry:** bring up the **free login shape** (SSH cold-bootstrap once, or reuse an online endpoint — `reused=True`, zero SSH), run the facility's allocation command over Compute, return `needs_account`; `provisioning` ⇒ still warming; a refused first SSH is explained (`NO SSH ACCESS to <host> as <user>` / `CANNOT REACH <host>`, [[Standing up the endpoint]]). **MEP entry:** *attach* only — `needs_account` with `reused=True` at once, compute-only, no allocation listing; the notice says whether an account is needed and that attaching doesn't test your identity mapping ([[facility-mep]]). A facility used before resolves from the **local cache** (`facilities.json`, keyed by `ssh_host` — [[state]]) with **no SSH probe**, then reuses the online endpoint (zero-SSH reconnect). **Not in the registry ⇒ discover, don't interrogate:** pass `ssh_host` and the tool **probes the login node**, returning `proposed_facility_details` with a draft [[models\|FacilityDetails]] to confirm; call again with `details=…` to register a **session-local** entry (never indexed) and proceed (the login-shape canary validates it). A host needing interactive login (password/Duo) returns `needs_preauth` + a `preauth_command` for the user to run in **their own terminal** — the secret never reaches the agent ([[MFA and interactive SSH auth]]). With no host ⇒ `needs_facility_details`. See [[Globus index discovery channel]]. |

> [!note] Two execution channels
> `run_shell`/`reset_session` ride [[Two-channel architecture|AMQP]] (the warm block or the login shape). `login_shell` is the only tool that opens a fresh SSH — reserved for cold-start discovery.

> [!note] The selection flow
> `list_facilities` → `connect_facility(facility)` → pick an allocation → `ensure_endpoint_up(account=…, partition=…, confirm_spend=True)`. Machine + allocation are **agent-chosen at runtime** ([[Facility catalog]]); a machine can also be pinned at startup with `HPC_BRIDGE_MACHINE`. The Globus login is folded into the first `connect_facility` (or `authenticate` explicitly).

> [!note] Compute-only facilities (a facility MEP)
> Every tool that takes a `shape` runs `_shape_reject` first ([[server]]): on a [[facility-mep|MEP]] `shape="login"` — and `login_shell` — are refused with a notice, every shape is billed, `stop_endpoint` drains (terminal), `teardown_endpoint` detaches, and the first billed start is where a missing account surfaces as a terminal `NO ACCOUNT`.
