# The MCP tools

> [!abstract] Role
> The agent-facing surface — **fifteen** tools, all declared in [[server]], all returning structured [[models|Pydantic results]] (failures come back as outcomes, never raw crashes).

## Stand up & run

| Tool | Returns | What it does |
|---|---|---|
| `ensure_endpoint_up(shape="compute", partition=None, confirm_spend=False, account=None, cores=None, memory_gb=None, gpus=None, nodes=None, whole_node=None)` | `EndpointStatus` | Provision/probe the endpoint; reports `up` only once a **worker answers a canary** ([[Warmth, the canary & cold-start]]), else `provisioning` — whose notice carries the pilot's real scheduler state (queued / held / "no pilot → likely rejected", [#32](https://github.com/globus-labs/hpc-bridge/issues/32)) or the last dispatch failure. A billed `compute` block won't start without `confirm_spend=True` → `needs_confirmation`, whose `block` (and notice head) names the block: queue and account with their sources, nodes, walltime, the most node-hours it can bill; the call that newly confirmed carries the same `block` as a receipt (a re-confirming poll does not); a partition or account the facility's endpoint would drop is refused (`down`). `partition` and `account` (the chosen allocation) select the **scheduler target** — a Slurm partition or PBS queue — and persist for the session, across a `stop_endpoint` too (refused while a task is still running); changing either on a confirmed block answers `needs_confirmation` unless the call carries `confirm_spend=True`; that answer, or the confirming call's own, says what becomes of the old block. An account-required facility (MEP or SSH) answers `needs_account` to a confirm with no account. On a facility MEP a refused identity mapping is a **terminal `down`** saying `NO ACCOUNT` and naming the identity — not a queue wait, don't poll ([[facility-mep]]). |
| `run_shell(command, session_id="default", shape="compute")` | `ShellOutcome` | Run a command on the warm block (`shape="compute"`) or the login node (`shape="login"`, free — the no-SSH discovery channel; **refused on a compute-only MEP**; a job *submitted* by hand from either shape is billed, and the result's notice says so — [[Resource shapes & the spend floor]]). Cold endpoint → `cold_start` (no hang). A command that outlives the sync-wait comes back `running` + a `task_id` (**not** cut — it runs up to the block walltime) → retrieve it with `poll_task`. cwd/env persist per session ([[Session continuity]]). Long output keeps only its **end** (16,000 chars per stream), opening with a marker that says what was dropped, and the `notice` says to redirect to a file and read ranges ([[dispatch]] `for_agent`). A result over Compute's 10 MiB limit comes back `failed` with `exit_code=None`: the command ran, its output and exit code are lost. |
| `poll_task(task_id, wait=0.0)` | `ShellOutcome` | Retrieve a long task's result: `complete` once it finishes, else `running` (poll again); `wait` optionally blocks up to N seconds. This is what lets long work be a *foreground task* instead of a detached process — a running task keeps the block busy, so it's never idle-released ([[Cost control]], [#21](https://github.com/globus-labs/hpc-bridge/issues/21)). A pending task whose endpoint is unbound or reports offline is **ORPHANED**: a terminal `failed` (stop polling; reconnect and re-run), never `running` forever ([#44](https://github.com/globus-labs/hpc-bridge/issues/44)). One still pending past its ceiling stays `running`, and its notice says it may be queued behind another task or a relaunching block, or lost (keep polling, or abandon it as its notice says for its shape: a login task does not hold stop, but holds its session and the login worker). On a facility MEP, once a compute task is well past its ceiling, it is presumed lost and no longer holds stop or the detach. Its output is cut like `run_shell`'s. |
| `reset_session(session_id="default", shape="compute")` | `ShellOutcome` | Clear a session's persisted cwd + environment (per shape). A session with a task still running is busy — reset (like a second `run_shell`) is refused until it's polled. A reset still queued past the sync-wait comes back `running` + a `task_id`, like `run_shell`. |
| `stop_endpoint()` | `EndpointStatus` | Release the billed block over the login endpoint (AMQP, no SSH) via the scheduler's own cancel (`scancel` on Slurm, `qdel` on PBS); **leave the login-node endpoint online** for a zero-SSH reconnect. "Stop" = stop spending, not tear down ([[Cost control]]). Retries a cold release channel to confirm; `status="down"` = cancel confirmed (or nothing to cancel: a submission the scheduler rejected) AND no check of hpc-bridge's still queued on the endpoint, `status="draining"` = **unconfirmed** — the channel was cold, a scheduler command failed, or a check of ours is still queued and the endpoint can start a block to run it; the notice names it, and a pilot that died before it (re-call in about a minute; a check that stays queued ends with `teardown_endpoint`; [#24](https://github.com/globus-labs/hpc-bridge/issues/24)). On an endpoint hpc-bridge configured, the stop waits up to 90 s for that check to be given up, so one call usually ends `down` (on one configured by an earlier plugin, only `teardown_endpoint` ends a queued check); a check the service still lists as queued after that wait, whose own user endpoint the login node shows received it, failed it with bad state and stopped for good (no process, and its manager neither revived nor restarted it), is settled (its report of the failure was lost, a globus-compute-endpoint race) and named in the `down` ([[server]] `_settle_by_evidence`); the whole call takes at most 180 s, and a restarted server still sees the checks its predecessor sent. `spend_stopped` is true only for such a `down`. On a facility MEP **no cancel is issued** (no cancel channel): `draining` is **final**, the notice leads with "NO CANCEL WAS ISSUED" and names the block's scheduler job (`block_job_id`), the latest it can bill until, and the user's `scancel`/`qdel <id>`; `spend_stopped` is never true there ([#178](https://github.com/globus-labs/hpc-bridge/issues/178)). On either kind, stop is **refused** (`up`) while our work holds the block: a running task, a `run_shell` still in its sync-wait, or the command of a call the client cancelled (cancelling a call does not stop its command; `poll_task` it). |
| `teardown_endpoint()` | `EndpointStatus` | The explicit "destroy it entirely": `gce stop` + `delete` over SSH and clear all state — for when the user insists on removing the login endpoint (normally it's left online for reuse). After it, don't `run_shell` (that re-provisions a fresh one). On a facility MEP it only **detaches** (nothing of ours to destroy): `down` for our state, while the block bills on — the same notice and fields as a MEP stop. Refused like stop while our work holds the block. |
| `login_shell(command)` | `LoginShellResult` | Read-only command on the login node over a **fresh SSH** connection — the cold-start discovery escape hatch. Prefer `run_shell(shape="login")` once an endpoint is up ([[Discovery today]]). Requires a connected SSH facility; refused with a notice on a compute-only MEP (no SSH, no login node). Long output keeps its marked end, like `run_shell`'s. A job the command submits is billed like a block; the notice says so. |
| `authenticate(force=False, mode=None)` | `LoginStatus` | The Globus login gate as a tool: `logged_in` (also when the browser flow lands during the call's wait), or `needs_login` with a `login_url` — browser loopback flow (opens the browser, waits up to 90 s; the URL is returned to show only if no browser opened; single-use) or Globus's paste-back auth-code page when headless / `mode="paste"`. 10-min TTL; `force=True` re-consents. Minimum consent = the Compute SDK's endpoint floor; Search is not requested (registry reads are anonymous). |
| `complete_login(code)` | `LoginStatus` | Paste-back completion: exchanges the one-time auth code the user pasted from Globus's auth-code page and stores the tokens in the Compute SDK's `storage.db` under the SDK's own client id (the one the remote endpoint refreshes with). Refused once the attempt expired. Never a password. |

## Batches (phase 1: [[batch]], [[ledger]])

| Tool | Returns | What it does |
|---|---|---|
| `run_batch(command=None, rows=None, task_walltime_s=None, results_dir=None, session_id="default", shape="compute", idempotent=False, confirm_spend=False, batch_id=None)` | `BatchStatus` | One command over many rows on the session's confirmed compute block: `{name}` for a row's fields (shell-quoted), `{row}`, `{index}`. At most `capacity` tasks out at once (the block's workers less one kept for interactive work); a row is sent only while the block has `task_walltime_s` + 30 s of walltime left, read from inside the block (unknown admits nothing); a `task_walltime_s` the block's walltime cannot fit is refused. The spend floor is `ensure_endpoint_up`'s (`needs_confirmation` with `block`, nothing recorded; `confirm_spend=True` confirms one block). A batch whose block ends (its walltime, a reap, a stop, a restart, a drain) pauses at `needs_confirmation` with a `reason`; `run_batch(batch_id=…, confirm_spend=True)` resumes it, refused when another live server holds the batch. |
| `status(id, detail="summary", offset=0, limit=50, wait_s=0.0)` | `BatchStatus` | Counts by state (`backlog`, `in_flight`, `done`, `failed`, `lost`, `presumed_lost`, `submit_unknown`, `cancelled`), and the rows themselves with `detail="failed"` or `"page"`: exit code, `tail`, `stdout_path` (capped output on the facility), `job_id`, `started_at`, `settled_by`. `wait_s` (≤ 60) waits for a change. Collects results and keeps a running batch admitting; never resumes a paused one. From another server it reads the ledger (`owner`); for a batch whose server is gone it takes the lease over, pulls by REST and asks again. Ids other than `batch-…` are refused (phase 2+). |
| `cancel(id, mode="drain")` | `CancelResult` | `drain`: admit nothing more, keep the backlog (resumable). `abort`: cancel the backlog and end what is in flight — the `CANCELLED` marker, which each task's wrapper watches and kills its command on (rc 143); never the block. `draining` while a task is out, `down` once none is; `blocks_left` names the session's block, which bills until `stop_endpoint`. Any server may cancel (recorded in the ledger for the holder). |

`stop_endpoint` pauses every batch under the lock before anything is released and refuses (`up`) while a batch's tasks are out, naming `cancel(id, 'abort')`. `poll_task` also takes a task's Globus id (`globus_task_id` on a `running` answer), answered from the ledger after a restart.

## Catalog selection (the agentic discovery front)

| Tool | Returns | What it does |
|---|---|---|
| `list_facilities(query="")` | `list[CatalogSummary]` | Browse the [[Facility catalog]] (the public registry, read anonymously — works with no config and no login). Agent-safe summaries — identity + provenance + **how you get in** (`access`: `mep` = zero SSH but the facility must have mapped your Globus identity; `ssh` = an account + key-based SSH on the login host; `access_note` spells it out; `scheduler`), **no** executable config or raw UUIDs. No SSH, no spend. |
| `connect_facility(facility, ssh_host=None, details=None)` | `ConnectFacilityResult` | **The entry point for reaching any facility.** **Gated on Globus login first** — before the catalog read or any SSH: in browser mode the call opens the browser and **waits up to 90 s (`HPC_BRIDGE_LOGIN_WAIT_S`) for the redirect, then continues in the same call**; only a still-open, headless or paste login returns `needs_login` (see `authenticate`). Then it resolves the entry — explicit `details=` → **the registry** → the local BYO cache → probe ([[Facility catalog]]) — and binds it. **SSH entry:** bring up the **free login shape** (SSH cold-bootstrap once, or reuse an online endpoint — `reused=True`, zero SSH), run the facility's allocation command over Compute, return `needs_account`; `provisioning` ⇒ still warming; a refused first SSH is explained (`NO SSH ACCESS to <host> as <user>` / `CANNOT REACH <host>`, [[Standing up the endpoint]]). **MEP entry:** *attach* only — `needs_account` with `reused=True` at once, compute-only, no allocation listing; the notice says whether an account is needed and that attaching doesn't test your identity mapping ([[facility-mep]]). A facility used before resolves from the **local cache** (`facilities.json`, keyed by `ssh_host` — [[state]]) with **no SSH probe**, then reuses the online endpoint (zero-SSH reconnect). **Not in the registry ⇒ discover, don't interrogate:** pass `ssh_host` and the tool **probes the login node**, returning `proposed_facility_details` with a draft [[models\|FacilityDetails]] to confirm; call again with `details=…` to register a **session-local** entry (never indexed) and proceed (the login-shape canary validates it). A host needing interactive login (password/Duo) returns `needs_preauth` + a `preauth_command` for the user to run in **their own terminal** — the secret never reaches the agent ([[MFA and interactive SSH auth]]). With no host ⇒ `needs_facility_details`. See [[Globus index discovery channel]]. |

> [!note] Two execution channels
> `run_shell`/`reset_session` ride [[Two-channel architecture|AMQP]] (the warm block or the login shape). `login_shell` is the only tool that opens a fresh SSH — reserved for cold-start discovery.

> [!note] The selection flow
> `list_facilities` → `connect_facility(facility)` (its `block`: the first block's terms) → ask the user for what they haven't said (the account, the queue) → `ensure_endpoint_up(account=…, partition=…, confirm_spend=True)`. Machine + allocation are **agent-chosen at runtime** ([[Facility catalog]]); a machine can also be pinned at startup with `HPC_BRIDGE_MACHINE`. The Globus login is folded into the first `connect_facility` (or `authenticate` explicitly).

> [!note] Before a facility is bound
> With no machine pinned and none connected, `ensure_endpoint_up`, `run_shell`, `reset_session` and `login_shell` all answer the same **"No facility connected"** notice (call `connect_facility` first; nothing was started) — or, when the last `connect_facility` returned `proposed_facility_details`, a notice saying to finish it with `connect_facility(<id>, details=…)`; when it returned `needs_preauth`, one pointing at `complete_preauth` / the user's own terminal (not another connect). No local endpoint is ever stood up in the facility's place ([[facility-local]]; local dev is an endpoint you run, named by `HPC_BRIDGE_ENDPOINT_ID`, [[Configuration]]).

> [!note] Compute-only facilities (a facility MEP)
> Every tool that takes a `shape` runs `_shape_reject` first ([[server]]): on a [[facility-mep|MEP]] `shape="login"` — and `login_shell` — are refused with a notice, every shape is billed, `stop_endpoint` drains (terminal, no cancel issued — the notice names the block and the user's cancel command), `teardown_endpoint` detaches, and the first billed start is where a missing account surfaces as a terminal `NO ACCOUNT`.

**`ensure_endpoint_up`'s size (2026-10-24, [[Resource requests]]).** `cores`, `memory_gb`, `gpus` (per node),
`nodes` and `whole_node` ask for a slice of a node or whole nodes; they persist for the session and a change re-asks
spend. With none on a per-core partition the terms propose a slice; `nodes` > 1 is one shell on the first node. A size
the partition cannot give or the facility's template does not take is refused before any submit, saying why.
