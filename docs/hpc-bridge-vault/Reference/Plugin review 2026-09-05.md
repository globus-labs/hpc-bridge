# Plugin review 2026-09-05 — design, dependencies, bugs

Tree reviewed: `feat/mep-m1` == `origin/main` @ `0ca7f80` (#92, 0.1.5). Read-only; no live connects; nothing under `agentic/` was run. Local runs this pass: `python -m pytest -q` → **1 failed, 515 passed, 2 skipped**; `uv run ruff check .` clean; mypy clean (dimension runs). Line numbers refer to this tree.

## Executive summary

1. **Not ready to tag.** Three things gate the next beta tag; everything else can ride 0.1.6.
2. **`main` is CI-red** (run 33931497356, py3.11 and py3.14): 13 tests in `tests/test_catalog_flow.py` patch `server.make_catalog`, an inert re-export, so the "hermetic" tier queries the live Globus Search registry and writes into the developer's real `~/.hpc-bridge/catalog-cache/`. #92 changed the registry and the tier went red. The fix is one identifier at 13 sites plus a tripwire.
3. **`teardown_endpoint` lies about a credential.** It reports `down`, "manager gce-stopped" and "token copy removed" from booleans that are never measured; on every BYO MFA facility the preauth gate does not fire, so once the user's 1-hour SSH master has expired every login-node op fails silently and the tool declares a torn-down endpoint whose manager is still running and whose token store is still on the login node — and deletes the only record that would let a later teardown remove it.
4. **Two regressions from the 09-04 teardown work:** the login-node pin is overwritten with `None` when an already-running endpoint is adopted (#79 removed the guard), and `_finish_teardown` resolves `app.facility` lazily so a concurrent `connect_facility` makes the teardown destroy the *new* facility's endpoint.
5. **Credential seeding can overwrite a user's pre-existing remote `storage.db`** whenever `whoami` fails for a reason other than absence (env_setup failure, scope mismatch, auth.globus.org unreachable), then marks it as ours to delete.
6. **Three spend-report defects:** the MEP idle-release window quoted to the agent ("~600s") is hpc-bridge's own default, never the facility's; the spend clock always bills one node regardless of the block's `nodes_per_block`; SSH teardown keeps the compute clock running until the login-node ops finish.
7. **Dependencies are current and advisory-free.** `mcp` is on the last 1.x; the 2.x migration is ~15 lines (not the 3–4 the 09-03 review estimated — the mypy gate needs `Context[AppCtx, Any]` on 11 tools) and belongs after V1. mypy is unpinned in CI; the GitHub Actions are several majors behind.
8. **No LICENSE anywhere** — file, `pyproject.toml`, `plugin.json`, `marketplace.json`; GitHub reports `license: null`. A public marketplace plugin with no grant. Release gate.
9. **Docs did not follow #92 or 0.1.2:** HANDOFF, the vault, `adding-a-facility.md` and SKILL.md still describe the retired Anvil-SSH entry and `globus1`; three user-doc passages still say the agent never handles a one-time code; the Expanse registry description (live) says the same; `README.md:55` names a version and a tag that do not exist.
10. **Verdict:** fix items 1–2 of "Fix now" and add the LICENSE, then tag; items 3–6 and the docs sweep are a second PR the same week. The design section is the plan for the state-machine gaps that keep producing these bugs.

## Fix now

### 1. HIGH — `teardown_endpoint` reports `down`, "gce-stopped" and "token copy removed" without measuring any of them; BYO MFA facilities are never gated

**Where.** `src/hpc_bridge/facility/remote.py:519-522` (`stop` discards the SSH rc), `:573-575` (`wipe_storage_db` drops the result), `:984-987` (`wiped = True` unconditionally), `:988-989` (`store.remove` regardless of outcome), `:993` (`ssh_closed` derived from `control_dir is not None`, not from `close()`); `src/hpc_bridge/server.py:681-703` (`_finish_teardown` answers `down` and clears state even when `teardown()` raised); `server.py:706-717` (`_teardown_preauth_gate` fires only when `auth_method == "mfa-otp"`); `src/hpc_bridge/binding.py:243-284` (`_entry_from_details` never sets `auth_method`; `FacilityDetails` has no such field; `connect.py:378-381` records nothing on `NeedsPreauth`). Only `catalog/seed/sdsc-expanse.yaml:15` carries `mfa-otp` today.

**Failing sequence.** BYO MFA facility (`connect_facility(details=…)` after the `needs_preauth` → `complete_preauth` handoff). Hours later the user's `ssh -fN` master (`ControlPersist=1h`, `remote.py:124`) is gone. `teardown_endpoint` → gate returns `None` (`auth_method` is the CatalogEntry default `ssh-key`) → `_release_blocks_over_login` → `teardown()`: `stop()` rc=255 under `BatchMode` ignored; `cancel_blocks` → `[]`; `delete()` → `False`; `wipe_storage_db()` rc dropped, then `wiped = True`; `store.remove` deletes the record carrying `seeded_credentials`; `ssh_closed = True`. `_finish_teardown` reports `status="down"`, "manager gce-stopped, but DELETE FAILED … the Globus token copy hpc-bridge placed on the login node removed; the shared SSH connection … was closed", and `_drop_all_shapes`. Reality: manager running, `storage.db` still on the login node, pin and seeded-flag gone — so no later teardown can ever wipe the bearer token (`_seeded_by_us`, `remote.py:916-924`, reads that record). The trailing "It will NOT be reused" is false too: the registration survives and the next `connect_facility`'s `find_online_endpoint` re-adopts it. Reproduced hermetically with every SSH op returning rc=255. `tests/test_security_review.py:431-501` and `tests/test_server.py:678-720` only exercise fakes where every op succeeds or `auth_method = "mfa-otp"`.

**Fix.** Make `stop()`/`wipe_storage_db()` return their rc and have `teardown()` report `stopped`/`credentials_wiped` from them; remove the `LoginNodeStore` record only when `deleted` is `True`; in `_finish_teardown` return `status="up"` (or a new `teardown_failed`) and keep state when `stopped` is `False` or `teardown()` raised. Gate on evidence, not the curated flag: run `_teardown_preauth_gate` whenever the target has a `control_dir` and no master is alive, or record `auth_method="mfa-otp"` on the session entry when the probe raised `NeedsPreauth`. Add the rc=255 fake-CLI test.

### 3. MEDIUM — teardown's unlocked window: the background task tears down whatever facility is bound when it starts, two calls run `teardown()` twice, and a stale one-time-code handoff survives a re-bind

**Where.** `src/hpc_bridge/server.py:623` (reads `eid`), `:645-646` (two awaits with no `app.lock`), `:649` (`create_task(_finish_teardown(app, eid))` — only `eid` is passed), `:676` (`getattr(app.facility, "teardown", None)` on the task's first step), `:621` vs `:649` (`teardown_task is None` check and assignment straddle the awaits); `src/hpc_bridge/connect.py:216-222` (re-bind block sets facility/machine/shapes/state/scratch_root — never `pending_preauth`/`preauth_resume`; never consults `teardown_task`); `server.py:414-435` (`_complete_preauth` never checks `pending[0]` against `app.machine`); `connect.py:378-381` (`_propose_or_ask` sets `pending_preauth` but not `preauth_resume`, so `server.py:429`'s `app.preauth_resume or …` can speak a stale `"teardown_endpoint()"`). `context.py:113` claims the lock "serializes … teardown". The existing guard `:692-695` and test `tests/test_server.py:762-789` protect only `app.state`.

**Failing sequences (all reproduced hermetically).** (a) `teardown_endpoint` and `connect_facility(other)` in one parallel tool batch: the rebind lands during `:645`, `:646` or between `create_task` and the task's first step → the task calls the **new** facility's `teardown(old_eid)`: `gce stop`/`delete` of `hpc-bridge-<new_host>` on the new login node, `store.remove` of its pin, `wipe_storage_db` if seeded, `cli.close()` (`remote.py:976-993`). (b) Two overlapping `teardown_endpoint` calls both run `facility.teardown('eid-1')`. (c) `connect(expanse)` → `needs_preauth`; `connect(anvil)` → `needs_account`; `complete_preauth(code)` opens a ControlMaster to Expanse and answers "Call connect_facility('expanse') again" — a re-bind that drops Anvil's shapes.

**Fix.** Under `app.lock` at `:623`, snapshot `(facility, eid)` and set `app.teardown_task` (or a sentinel) before the first await; thread the snapshot through `_login_runner`, `_teardown_preauth_gate` and `_finish_teardown` (capturing only before `create_task` is not enough — the window opens at `:645`). In the re-bind block clear `pending_preauth` and `preauth_resume`; have `_complete_preauth` refuse when `pending[0] != app.machine`; have `_propose_or_ask` set `preauth_resume`. On the follow-up teardown call, if `app.state.endpoint_id` differs from the finished task's `eid`, return the old result but say the new endpoint is still up.

### 4. MEDIUM — adopting an already-running endpoint overwrites the stored login-node pin with `None` (regression from #79)

**Where.** `src/hpc_bridge/facility/remote.py:872-874` (early return only when the web service says online), `:930-937` (`provision` returns `EndpointHandle(…, reused=True)` with `login_host=None` when `gce list` says Running), `:898-913` (`bootstrap` then `store.put`s a fresh record unconditionally — `LoginNodeStore.put` replaces the row), `:497-498` (`start()`'s adoption branch reaches the same overwrite). `git show f9b0a85^` shows the former guard `if handle.login_host is not None and self.store …`; #79 removed it to persist `seeded_credentials` and the commit message says "The record is now written regardless (login_host may be None)". The docstring `:863-865` and comment `:932-933` still promise the prior node is kept. `binding.py:63-69` is the only pin consumer.

**Failing sequence.** Store holds `login_host="login03.anvil.rcac.purdue.edu"`; `find_online_endpoint` returns `None` (web error swallowed at `:1026-1029`, or manager not yet reported online); `cli.status → "running"` → `bootstrap` writes `login_host=None`. Next session's control-plane SSH (teardown, `login_exec`) goes to the round-robin alias — exactly the orphaning the pin exists to prevent. `tests/test_remote_facility.py:355-363` asserts `handle.login_host is None` but never checks the store.

**Fix.** Merge, as `:893-895` already does for `seeded_credentials`: `prior = self.store.get(alias, name)`; `login_host=handle.login_host or (prior.login_host if prior else None)`. Add a test mirroring the sequence.

### 5. MEDIUM — credential seeding overwrites a pre-existing remote `storage.db` and then flags it as ours to delete

**Where.** `src/hpc_bridge/facility/remote.py:876` (seed iff `not await self.cli.whoami()`), `:655-658` (`whoami` is `rc == 0` of `<env_setup> && globus-compute-endpoint whoami`), `:470-471` (`base64 -d > "$HOME/.globus_compute/storage.db"`, no existence check), `:888-892` (`seeded_credentials=True` written before provision), `:985-987` (teardown `rm -f`s it). The teardown docstring `:972-975` promises "a token store already on the login node … is never ours to delete."

**Failing sequence.** A store IS present but `whoami` exits non-zero because `env_setup` failed (the registry seeds run `curl | sh`, `uv venv`, `uv pip install` inside it), gce is not on `PATH`, the store's tokens do not satisfy the pinned gce's scopes (`app.login_required()`), or auth.globus.org is unreachable from the login node (`userinfo()` is a live round-trip in gce 4.15's `whoami`). hpc-bridge overwrites the user's credential at seed time and later deletes the replacement. A timeout does not trigger it (`ssh_exec` re-raises). `tests/test_remote_facility.py:332-337` (`_BootstrapCLI.whoami = remote_db_present`) models whoami-failure as db-absent, so the case is untested.

**Fix.** In `seed_storage_db`, refuse to clobber: `[ -e "$db" ] && { echo HPCB_EXISTS; exit 3; }` before the write, surfaced as "a token store already exists on <host> but `whoami` failed: <stderr> — fix env_setup/network; hpc-bridge will not replace a credential it did not create". Or move it aside (`storage.db.pre-hpc-bridge`) and restore in `wipe_storage_db`. Set `seeded_credentials=True` only when the pre-check confirmed absence. Add the present-db/whoami-fails test.

### 6. MEDIUM — three numbers the agent relays to the user are wrong: the MEP idle window, the block's node count, and spend during SSH teardown

**(a) The "~600s" idle-release window is hpc-bridge's default, not the facility's.** `src/hpc_bridge/context.py:129-132` falls back to `app.profile.max_idletime_s` (`profile.py:13`, hard-coded 600) because nothing populates `MEPFacility.max_idletime_s`: `from_entry` (`facility/mep.py:109-116`, the only production path via `binding.py:105`) omits it and `CatalogEntry` has no idle field. Verified for anvil, delta and globus-cluster: all `None → 600`. `_stop_mep` (`server.py:524,533`) and `_billed_bounds_note` (`notices.py:144-149`) therefore quote 600 on every MEP; SKILL.md:25 tells the agent "the notice names the window" and to relay it as the spend-stop bound. It is coincidentally right on globus-labs (its template hard-codes `max_idletime: 600.0`), unpublished on Anvil/Delta, and 240 s on Polaris (`Reference/MEP facilities survey.md:35`). The docstring at `context.py:130`, `Concepts/Cost control.md:19` and `Review 2026-09-03 — code quality` #6 all assume the facility's value flows through. **Fix:** add an idle field to the MEP entry (or read it from `load_template`'s metadata) and pass it in `from_entry`; when unknown, say "the facility's idle window (not known to hpc-bridge)" instead of a number.

**(b) The spend clock and the confirm-spend notice always bill one node.** `src/hpc_bridge/cost.py:34,58` and `notices.py:154` read `app.profile.nodes_per_block`, which is the never-set `Profile` default (`server.py:165` builds `Profile(mode=…)` only). The block's real node count is in `rt.user_endpoint_config["nodes_per_block"]` (`remote.py:848` / `mep.py:103`, seeded by `warmth.py:46-64`). Reproduced with `nodes_per_block: 4`: notice says "(1 node(s))", `session_spend` under-reports 4×. Latent today (all seeds use 1; `ensure_endpoint_up` and `FacilityDetails` cannot set it) but the registry schema permits it and `Modules/profile.md` states the unwired intent. **Fix:** read the node count from the UEC, as `_billed_bounds_note` already reads `walltime`; put "N node(s) × walltime" in the `needs_confirmation` notice; fix `docs/user/costs-and-stopping.md:13` ("one node").

**(c) SSH teardown keeps the compute clock running.** `server.py:645` releases the block but never calls `warmth._drop_compute_shape` (as `_stop_endpoint` does at `:562`); banking happens only at `:692-695` after `teardown()` (~3 min on Expanse), or never on the preauth-gate path (`:724-732` returns `up` with `_total_session_spend` still counting). **Fix:** call `_drop_compute_shape` after the release and add `dropped` to the gate/`tearing_down`/final spend, matching the MEP branch at `:630-637`.

### Smaller fixes (low — bundle into the same PR)

### The mcp 2.x migration plan (post-V1, one PR)

The 09-03 review called it four lines. Applying exactly those to a scratch copy under mcp 2.1.1 gives an identical unit-tier outcome but **11 mypy `arg-type` errors**: 2.x's `Context` is `Generic[LifespanContextT, RequestT]` with `LifespanContextT` defaulting to `dict[str, Any]`, so the bare `ctx: Context` annotations stop typing `lifespan_context` as `AppCtx`. The complete change:

1. `server.py:10` → `from mcp.server.mcpserver import Context, MCPServer`; `:149` `lifespan(server: MCPServer)`; `:183` `MCPServer("endpoint", lifespan=lifespan)` (the name mirrors the `.mcp.json` key — keep it); `:950` `mcp.run()` unchanged.

3. `pyproject.toml:6` → `mcp>=2,<3` (the harness's `claude-agent-sdk==0.2.152` allows `mcp<3`); `uv lock` (2.x swaps `httpx` for `httpx2` and splits `mcp-types`).

## Design

Ordered by what each step buys. Items 3 and 5 are known, deferred debt (Review 2 2026-09-03 "also-after"; Review 2 #7) — restated only where a Fix-now item makes the moment right.

**1. Give the state machine a "manager offline" value.** `BlockState` (`lifecycle.py:9`) is `warm | cold | provisioning`; `probe` (`:23`) maps `manager_online() == False` onto `provisioning`. `warmth._provision` bootstraps only when `endpoint_id is None`, so a manager that dies mid-session (login-node reboot, external `gce stop`) is never re-stood-up, and `_ensure_endpoint_up`'s only offline disambiguation (`server.py:297-307`) is MEP-only. Reproduced: with `manager_up=False` on a login-shaped facility, `ensure_endpoint_up` answers `provisioning` / "allocating nodes…" forever and `run_shell` answers `cold_start`; the same state through `_stop_endpoint` correctly says "OFFLINE … (ORPHANED)" because that tool and `_poll_task` were given `_endpoint_gone` (09-03 bugs #6, #44) individually. SKILL.md:37 tells the agent to keep polling. **Step:** widen `ProvisionResult` (`lifecycle.py:11`) with `"manager_offline"`; return it from `_provision` when `probe` says `provisioning` for an `endpoint_id` this call did not just bootstrap and the manager reports offline past `PROVISION_GRACE_S`; map it to `status="down"` in `_ensure_endpoint_up` (reuse `_stop_endpoint`'s text, `server.py:579-583`) and to a terminal `failed` in `_cold_outcome`. **De-risks:** the endless-wait class for SSH facilities, and replaces three per-tool special cases (`_stop_endpoint`, `_poll_task`, the MEP branch) with one value.

**2. Stop overloading `EndpointStatus.status`, and type `shape`.** `status` (`models.py:39`) has no failure value, so `down` means "confirmed stop", "detached", "no endpoint", "NO ACCOUNT" and "refused 3×" (15 sites in `server.py`), discriminated only by the notice — documented design, and the harness graders key on status, so I am not asking to change the semantics. The concrete gap: `ensure_endpoint_up(shape="foo")` escapes the structured contract — `_shape_reject` (`warmth.py:33`) guards only known-but-unsupported shapes, `_shape_runtime` raises `ValueError` (`warmth.py:49`), and the tool wrapper (`server.py:330-347`) has no catch, so the client gets an MCP `isError` string while `run_shell`/`reset_session` return `phase="failed"` for the same input. `shape` is a plain `str` in all three tool schemas. **Step:** `shape: Literal["login","compute"]` on the three tools (schema validation rejects junk before Python does); the same `except Exception → structured result` wrapper on `ensure_endpoint_up`/`stop_endpoint`/`teardown_endpoint` that the shell tools have; add `failed` to the Literal for input/internal errors so `down` stays "nothing of ours is running". **De-risks:** one demonstrated contract escape today; the `teardown_failed` state item 1 of Fix-now needs.

**3. Make the two facility access models explicit types — when the next facility kind arrives, not now.** `Facility` (`facility/base.py:18-23`) declares `name` + 3 methods; the runtime reads ~20 optional attributes through 26 `getattr` sites across 7 modules, including a dead `cli._target` probe (`notices.py:68` — both CLI classes expose `.target`) and the `config_template` isinstance dance (`warmth.py:53-59`). This is the vault's documented design (`Modules/facility-base.md:8`), `_has_login_shape` (`context.py:126`) is already the single derivation the 8 branch sites consume, and a new kind must be wired through `_facility_from_entry` (`binding.py:89-121`) so it cannot reach the defaults by accident. Not urgent; already deferred. **Incremental path:** (a) delete the `_target` probe and `_login_wait_s_UNUSED` (`notices.py:170`) now; (b) add `SshControlPlane` and `TemplateOwner` `runtime_checkable` Protocols with a `control_plane(app) -> SshControlPlane | None` accessor and extend `tests/test_facility_contract.py` to assert `SlurmFacility`/`MEPFacility` satisfy them; (c) replace the nested `getattr`s as they are touched. **De-risks:** a third facility kind failing the contract test instead of a live run; the vault's under-listing (7 of ~20 capabilities).

**4. Collect per-bind state into one record replaced wholesale at re-bind.** `pending_preauth`, `preauth_resume` and `teardown_task` live loose on `AppCtx` (`context.py:104-116`) and the re-bind block (`connect.py:216-222`) touches a hand-maintained subset — Fix-now item 3 is the bug that produces. Keep `bootstrapped_facilities` and `pending_facility_cache` session-wide: they are keyed by facility id and `connect(X)→connect(Y)→connect(X)` depends on that. **Step:** a `Bound` dataclass (`facility, machine, entry, scratch_root, pending_preauth, preauth_resume`) swapped as one object under the lock. **De-risks:** every future "state from the previous facility leaked" bug.

**5. Test hermeticity is a design property, not a convention.** `server.py:13-143` re-exports ~100 names "for imports only" with a comment telling tests not to patch them; the 13 mis-patched sites show the comment is not a mechanism. Do the tripwire first (Fix-now item 2 — ten lines; it would have caught this a week before #92), then delete the re-export blocks in a follow-up so tests and tools import from the owning modules. Route `plugin_data_dir()` through `_state_dir()` when `CLAUDE_PLUGIN_DATA` is unset so no unit test can touch the real cache.

**6. Measured, not intended, teardown.** The `remote.py` CLI methods return `None` for `stop`/`wipe_storage_db` and a bool derived from a string for `delete`; `teardown()` composes a report from intentions. Fix-now item 1 is the bug; the design rule to adopt is that every remote op returns its rc and every notice word ("stopped", "removed", "closed") is derived from one. The comment at `server.py:685` ("say what actually happened, not what was intended") already states the rule — the fields under it do not meet it.

**7. Finish the notice hoist where Fix-now item 6 touches it.** Known debt (Review 2 #7): `server.py` still holds 20 inline `notice=` literals and `connect.py` 6; the MEP-offline text exists twice with different wording (`server.py:304` vs `connect.py:322`); `_stop_endpoint` hard-codes "~10 min" at `server.py:591` beside the `_idle_release_s` helper used at `:524`. Fixing the idle-window number is the moment to hoist those two into `notices.py` builders.
