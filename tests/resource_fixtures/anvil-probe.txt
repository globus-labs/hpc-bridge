# Purdue Anvil's partitions, as the login-node probe (hpc_bridge.discovery._PROBE) frames them — from the live run of
# 2026-10-24 (session a1b8e88b), where the agent ran over the login shape:
#   sinfo -h -o '%P|%a|%l|%D|%c|%m|%F'
#   for p in debug shared standard wholenode; do scontrol show partition $p | … OverSubscribe|ExclusiveUser|DefMemPerCPU|TRESBillingWeights|QoS …; done
#   sacctmgr -nP show qos format=Name,MaxWall,MaxTRESPU
# Rewritten into the probe's lines: PSHAPE keeps the partition, cores and memory (MB) per node (that sinfo had no %G,
# so the GRES column is left out: GPU counts are not known from it); PDETAIL is each scontrol line as captured (the
# fields it asked for); QOS is Name|MaxTRES|MaxTRESPU (MaxTRES — the per-job cap — was not asked: empty). Not captured
# that day, and added here as the probe would read it: SELECT_TYPE (Anvil's `shared` partition shares nodes by core,
# which only select/cons_res or cons_tres do). `wide` and `gpu` had no scontrol line in the capture: their kind is not
# known. Account names and balances are left out.
